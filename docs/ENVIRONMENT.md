# Environment variables

Every environment variable the platform source reads (`packages/*/src`, `services/*/src`), one row each.
Names, defaults and meanings only; no estate values. `tools/tests/test_environment_doc.py` parses the
source with the AST and fails when a variable is read there but missing from this table, when a row
is no longer read by any source file, or when a row's Component column differs from the components
whose source names the variable.

**Machine-checked: the variable names and the Component column. Hand-maintained, not checked: Default,
Accepted values, Security impact and First read.** A changed default or parsing rule in the source passes
the test, so the source is the authority for those columns.

How to read it:

- **Component**: every package or service whose source names the variable, whether it reads it or passes
  it on (so a component may appear that only forwards the name).
- **Default**: what the code uses when the variable is unset, as read from the source.
- **Accepted values**: how the value is parsed. Parsing differs per variable: some switches arm only on
  `1`/`true`/`yes`/`on` (any case), some only on exactly `1`, and an unrecognised value is OFF for some and
  ON (fail closed) for others. Rely on this column, not on a guess from the name.
- **Security impact**: what unset or mistyped does. The six posture variables that fail open when unset
  (`FIELD_SHARED_SECRET`, `FIELD_OPERATOR_REQUIRE`, `FIELD_LEDGER_REQUIRE_SIGNING`,
  `FIELD_LEDGER_REQUIRE_CALLER_SIGNATURE`, `FORCE_GATEWAY_ENFORCE`, `FIELD_DOA_ROSTER`) are the ones the
  GB10 required-posture overlay (`integration/demo/docker-compose.gb10.required.yml`) makes mandatory.
- **First read**: the first read site found (file under `src/`, line), as a starting point.

The cells were characterised by reading the read sites (C-329, reviewer B-03) and spot-checked against the
source; the source is the authority. A variable read through a name built at run time (concatenation, an f-string, a loop variable) would
not appear in the scan (none exists today); the scan follows `os.environ`, its aliases and copies,
`os.getenv` (also imported bare), `in` tests and string constants held at module, class or function level.
