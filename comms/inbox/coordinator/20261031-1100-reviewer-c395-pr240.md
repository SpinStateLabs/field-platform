## OBJECTIONS FIRST
1. F-C395-1 LOW (false positive, backtracking): `_DYNAMIC_KEY = \bgithub\s*\[\s*(?!['"])` flags a harmless literal key written with a space after the bracket. Probed through `lint()`: `${{ github[ 'sha' ] }}` and `${{ github[ "sha" ] }}` are FLAGGED as script injection; `github['sha']` and `github["sha"]` are green. Cause: `\s*` can match zero spaces, leaving the space as the character the negative lookahead sees, which is not a quote. A workflow with that spacing would go red with a message about injection. Fail-closed, so not a security gap; a mutant that fixes it (`\[(?!\s*['"])`) survives all 119 tests because no test writes a spaced literal key.
