## OBJECTIONS FIRST
1. F-C437-1 MEDIUM-LOW (an unparsable time wins, and the cursor is sent to the API): when one side parses and the other does not, `_later` falls back to text. Digits sort before letters, so `_later("not-a-time", "2026-10-28T13:00:00Z")` is True and `_later("2026-10-28T13:00:00Z", "not-a-time")` is False. Reproduced with the cursor rule from `_read_events` (`if cursor is None or _later(processed, cursor): cursor = processed`): cursor `2026-10-28T13:00:00Z`, then an event with `processed_at` `"not-a-time"` makes the cursor `"not-a-time"`, and the two later real times (`14:00Z`, `15:00Z`) never replace it. `state.cursor` is what `_read_events` sends as `created_at_gte` on the next list call (core.py, `params["created_at_gte"] = state.cursor`), so the filter becomes garbage: an API that rejects it fails every read of that session (`list_failures`, no approvals), one that ignores it returns the whole history again (re-read, deduplicated by event id). The card said an unparsable string "must not move the cursor back"; here it moves the cursor to the garbage. `test_two_strings_that_are_not_times_compare_as_text_and_never_raise` asserts `_later("not-a-time", "2026-10-28T13:00:00Z") is True`, so the test pins that direction. The old code had the same property for a datetime cursor against an unparsable string (`"zzz"` sorts after `"2026-..."`), so this is not a regression; it is the remaining edge of F-C413-1. In production the API sends a timestamp or none (a missing value never reaches the comparison: `processed is not None`), so I know of no live path. Fix: a value that does not parse never replaces a cursor that does (return False when exactly one side parses), and an unparsable value never becomes the cursor.
2. LOW (assumption, stated by the code): a naive string or datetime is read as UTC, and a date-only string as midnight UTC. If the API ever sent naive local times these would mis-order; not known to happen.
3. LOW: the text fallback compares two unparsable strings as text (`"b" > "a"`), which is arbitrary; it cannot raise and only matters for values the API does not send.
