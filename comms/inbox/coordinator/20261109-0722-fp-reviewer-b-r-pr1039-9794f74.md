## Code read
`_domain_outcomes` now tests `isinstance(outcome, str)` before `outcome in counts` (a list or object is unhashable). A non-string outcome counts as an error with the fixed text `outcome is not a string`; a missing or string outcome keeps its old text. `fleet_halt` wraps the per-domain parsing in `try/except Exception` and records an unreadable answer as `ok: false, counts: None` with a fixed message, so later domains still get their kill. `_seg` (percent-encoding, total for any string) and `ServiceClient.post` (catches its own exceptions) cannot abort the loop. A domain whose kill returned 2xx but whose answer could not be read is reported not-ok: the fail-safe direction (the operator is told to verify).

## Measured outside this PR's stated scope (not a condition; same on main)
The domain list for a `/api/fleet/halt` with no explicit `domains` is built from the registry answer before the loop (`sorted({a.get("domain") or "general" ...})`, api.py:~832), outside the new guard. With a registry answer that has an odd entry, on the head (a scratch test with fake clients; nothing added to the PR branch):
| Registry answer | HTTP | Kills sent |
|---|---|---|
| all string domains | 200 | alpha, beta |
| one domain is an int, a list, or an object | 500 | none |
| an agent entry that is a string or null | 500 | none |
| empty or missing domain | 200 | alpha, general |
Main (347b72089) gives the same results. The registry validates `domain` as a string at registration, so this needs a damaged registry store (MEDIUM), but the effect is the whole fleet halt failing before one kill is sent, the worse form of what this PR fixes for one domain's answer. Worth its own card: validate the registry rows (skip or fail loudly per row) before the loop.
