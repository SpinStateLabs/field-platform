# C-170 reviewer report: services/force-gateway routing, enforce, judge and key paths (main 7b4d6f7)

VERDICT: the enforce path is fail-closed and well pinned; 181 mutants run, 160 killed, 21 survived, none on the authorize-or-refuse path. One posture-parsing edge (near-miss values leave the gateway an observer) and the untested upstream-error passthrough are the notable items.

OBJECTIONS FIRST
1. The earlier audits (C-58, C-104, C-115) covered the API-key path; this round adds routing, enforce and judge paths but mutates api.py and hygiene_judge.py only (not store.py, drift.py, telemetry.py).
2. 181 mutants from two generators is not a coverage figure; the 40 v2 mutants are a seeded sample of 529.
3. Findings about flag parsing are about shipped defaults being safe, which the descriptors do not guarantee for typos.

ASSUMPTIONS
1. Main 7b4d6f7; force-gateway suite 208 tests (7 s); api.py 1,077 lines: v1 127 mutants (115 killed, 12 survived), v2 sample 40 (34 killed, 6 survived); hygiene_judge.py 14 (11 killed, 3 survived). I read the `/v1/messages` entry (enforce checks), `_enforce_tool_blocks`, `_meter_usage`, `real_upstream` (earlier), the `resolve_*` functions. [HIGH]

REASONING
1. Enforce path (sound): with `FORCE_GATEWAY_ENFORCE=1` the route first requires `x-field-agent-id` and `x-field-token` (401, api.py:~860-866), then `_authorize` (sentinel check; refusal 403/503, ledgered `gateway.refused`), before the passthrough exemption and before any bypass window ("the Gateway's own trouble may drop instrumentation, never enforcement", :~858). `/health` reports `enforce`, `tool_check`, `tool_check_active`, `sentinel_url`. Mutants on this block were killed. Under enforce, the no-agent-id case in `_enforce_tool_blocks` (L577 `not agent_id`) is unreachable: the 401 comes first; that survivor is equivalent. [HIGH]
2. Key and TLS paths (pinned): `scrub_secret`/`_secret_forms` (23/23 killed in C-115, same code), `FORCE_GATEWAY_REQUIRE_TLS_UPSTREAM` refusal and `_warn_once` (W-mutants killed in C-115); in this round no new survivor in `real_upstream`, `_base_url_warning` or the scrub (only the already-recorded L143 `>= MIN_PREFIX_SCRUB + 4`, F-C115-2). [HIGH]
3. LOW-MEDIUM, F-C170-1: flag parsing. `resolve_enforce` and `resolve_tool_check` (api.py:281-290) are `os.environ.get(...) == "1"`. Probe: `1` -> True; `true`, `TRUE`, `yes`, `on`, `enforce`, ` 1`, `1 `, `2`, empty, unset -> False. The docstring frames it as "a near-miss never flips a security posture silently — it stays the observer"; for ENFORCE that is the less safe direction (the same shape as F-C157-3 for the sentinel: any typo means no enforcement), and `FORCE_GATEWAY_REQUIRE_TLS_UPSTREAM` (exact `"1"`) fails the same way (a typo means the key may travel over plain http, with only a warning). `/health` exposes `enforce`, so a probe can see it; nothing refuses to start. The mock switch (`FORCE_GATEWAY_MOCK == "1"`, `resolve_upstream`) is the case where exact-match is the safe direction. [HIGH]
4. LOW, F-C170-2: upstream error passthrough: api.py:921 and :935 `if status != 200: raise HTTPException(status, response)` forced False both SURVIVE: with the check lost, an upstream 4xx/5xx would be delivered as a 200 response carrying the error body (and run through tool-block enforcement); no test sends a non-200 upstream answer through `/v1/messages`. [HIGH on the survival]
5. LOW, F-C170-3: hygiene judge: hygiene_judge.py:119 `if not key: raise HygieneJudgeError("ANTHROPIC_API_KEY not set")` survives (a judge without a key would then send an unauthenticated request); :136 `resp.status_code != 200` raise survives (a non-200 would be parsed as a verdict); :170 `raw == "anthropic"` resolver branch. These are judge (telemetry) paths, not enforcement; failures degrade to "unjudged". [HIGH]
6. LOW, F-C170-4: remaining survivors: api.py:457, :707 (`store is None`), :507 (`ledger is None`), :610 (`stripped == 0`: nothing stripped), :637 (`sample_every <= 0`), :719 (`not name.startswith("coverage.")`), :1003 (`overhead_ms > latency_budget_ms` boundary), :1035 (routes with zero requests), v2: :404 (rounding digits), :542, :698, :779 (bypass cooldown default), :932, :955 (labels and defaults). [HIGH]
