## Objections first (FORCE)
1. Behaviour change for every caller of `make_http_client` (crosswalk suggestions, sentinel judge, gateway hygiene judge): a non-http(s) scheme (`ftp://`, `ws://`, `file://`) used to be refused with text naming scheme and host; it is now the fixed variable-only text. Operators lose the host hint; the PR flags this and no existing test pinned the old wording (PR body; my grep of the field-core suite agrees: 1962 passed).
2. `make_http_client` now refuses a URL with a scheme but no hostname (`http://`) before the cleartext check. A previously tolerated empty-host value therefore fails at client construction, not later. Intended fail-closed (HIGH).
3. The httpx wrap catches `ValueError`/`httpx.InvalidURL` from client construction and hides the cause (`from None`); a real httpx bug raising ValueError for a valid URL would read as "not a usable base URL" (LOW, and the PR keeps the cause suppressed on purpose so no URL text can leak).
