## Objections first (FORCE-O)
1. This is a key-handling command, so a test that cannot see the dangerous state is weaker than it looks. Three controls in `keygen` that the code comments promise are untested: truncation of a longer existing key under --force (H6), the chmod that brings an existing 0644 key down to 0600 under --force (H7), and the creation mode itself, whose window is not observable from the final file mode (H5; the final-mode test still catches a chmod to the wrong mode, H8).
2. The same-path check compares `out.resolve()` with `pub.resolve()`. It does not detect two names of one inode (a hard link): `--out k.pem --pub hard-link-to-k.pem --force` would still overwrite the private key with the public one. I did not run that case; I read the code (cli.py line 160). MEDIUM, in scope of the PR's stated goal ("--pub must not overwrite --out"). The test file covers a symlink and two spellings, not a hard link or a case-insensitive filesystem.
3. A symlink given as `--out` (pointing at some file) is followed by `os.open` with O_TRUNC, and with `--force` the target is truncated; the PR does not address this (pre-existing, not claimed).
Steelman: the diff is 8 lines and every branch it adds is hit by a test: same file, two spellings, symlink with --force, the success case, the 0600 mode, and the no-fallback failure; 13 of the 24 mutants die, including every mutant that removes or inverts the new refusal and every mutant that restores the default-mode fallback.
