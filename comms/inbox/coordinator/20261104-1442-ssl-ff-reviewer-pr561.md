## Objections first (FORCE-O)
1. A warning nobody reads changes nothing. The PR makes the open state visible in the log and deliberately refuses nothing (Don ruling D-21, quoted in the module docstring); a deployed estate that starts open still starts. That is the ruling, not a defect.
2. Operator `log-only` is not reported as open ("that layer is ON, it observes and records but does not refuse"). On the estate the roll-out is staged (log-only before enforce), so a service running log-only for weeks is silent in this line. The module says so and says what to widen; it is a policy choice a reader may dislike.
3. `warn_open` swallows every exception (`except Exception: return False`), so a bug in `open_settings` hides the warning silently; the test for that swallow exists (mutant B7 killed) but nothing logs that the warning failed. LOW.
4. The once-per-process memory is keyed by service name, so two apps created in one process under one name log once; a test fixture or reloader that creates the app twice stays quiet the second time. Intended.
Steelman: the line names only variable names (shape-filtered, `UPPER_SNAKE`, at most 64 characters), never a value, each of the 14 services calls it with the right operator-layer flag, and the second commit also removes the one place that echoed a bad `FIELD_OPERATOR_REQUIRE` value into the log.
