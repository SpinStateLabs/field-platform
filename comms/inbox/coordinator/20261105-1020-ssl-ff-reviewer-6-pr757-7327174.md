Mutant F5 (the broad `except Exception` narrowed to `ZeroDivisionError`) survives all 30 tests: the new tests exercise only live servers answering with a non-object or an object, so a connection refused, a timeout, an HTTP error or invalid JSON in `_health` is not run by this file. The code is unchanged there (the `except` is pre-existing); the risk is that the new `try` body now has a second statement and a later edit could narrow the net unseen. LOW.
2. The read is capped at 64 KiB (`r.read(65536)`); mutant F4 (65537) survives: the cap is not pinned (a body over the cap would then fail JSON parsing and be a named error; unchanged and untested). LOW.
3. The fix is in two places by design: `_health` stores `{"_error": "NotAnObject"}` for a non-object answer, and `check_health` also names a non-dict VALUE it is handed directly (a caller or test that builds the mapping itself). Both are pinned (F1, F2, F3, C1, C2, C3 killed). The order matters and is pinned: the non-dict test runs before `"_error" in h`, which would otherwise be True for the string `"_error"` (a case the test list includes) or a TypeError for a number.
4. `service_of` (a pure function) is pinned directly now: the service name must be a path component followed by the exact verb `serve`, the LAST argv element is never the service, a service-like prefix (`registry-ui`) does not match, and non-UTF-8 bytes elsewhere are tolerated (all six mutants S1 to S6 killed).
Steelman: before the change a `/health` that answered `[]`, a string, a number or `null` made `check_health` index into a non-dict (a traceback), so the run died without its `C5-RESULT:` line and CI's grep for it found nothing; now every non-object is a named problem, the run still ends with `C5-RESULT: FAIL`, exit 1 (asserted through `main` against a real local server).
