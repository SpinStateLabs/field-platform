## Objections first (failure conditions)
1. The gate reimplements pytest with an AST and a regex, and every difference is a hole: probe shows it ACCEPTS a citation whose test is skipped, xfailed, defined under `if False`, nested inside another test, a method of a non-collected class, in a file pytest never collects (`tools/helper.py::test_a`), shadowed by a later empty definition of the same name (`functions()` keeps the FIRST, `setdefault`), has its only assertion after a `return`, or is an assertion inside a never-called inner function. 12 of 13 such citation cases accepted (red). HIGH (run).
2. The keyword and assertion tests are substring and regex over the function's source text (`kw.lower() not in body.lower()`; `re.search(r"\bassert\b|pytest\.raises|\.raises\(", body)`): the keyword in a comment or docstring, `assert True`, or `"pytest.raises widget"` as a string all satisfy it. Probe red, 3 cases. (Reviewer F-PR308-2 already named the comment case; the other shapes are new.)
3. The commit check is `f"def {name}" in content`: a commit that contained only `def test_x_other` satisfies a citation of `test_x`. Probe red. HIGH.
4. The banned-word check exempts any LINE that contains "never" or "not a " anywhere: "never down and is certified by us" and "Never mind: compliant with SOC 2" pass (probe red, 4 cases; F-PR308-3 named the idea, the probe makes it pinnable). It also scans only three files (`PUBLIC`: the evidence file, README.md, ROADMAP.md): STATE.md, every service README and docs/ are not scanned for a certification or compliance claim.
5. Environment: the gate fails with 79 "not an ancestor of HEAD" errors on a shallow checkout (my cloned workspace was depth 50; PASS after a full fetch). CI's default checkout depth is 1, so wiring the gate into the existing jobs as-is turns it red for a reason unrelated to the claims. HIGH (run: shallow FAIL (79), full PASS (0 problems, 80 Enforced, 39 Declared)).
Steelman: for the actual drift it targets (a cited file renamed, a test deleted, a README row flipped) the gate is useful, and it passes on the head with full history. The holes need an author who wants to deceive; the gate's value is as a smoke alarm for honest drift, which is not the same as the words being "test/CI-proven".

## Recommendation (the structural fix, not a longer list)
1. Replace the AST reimplementation with pytest itself: for every cited `path::name`, run `pytest --collect-only -q path::name` (proves it is collected and spelled right) and then `pytest -q path::name` (proves it runs and passes; a skipped or xfailed test reports as such and the gate fails on anything but a pass). Then the invariant "collected, runs, can fail" is pytest's, not ours. Cost: the gate needs each service's dependencies installed (it already has them in CI) and runs 80 tests (the citations), about minutes, offline.
2. "Names the word" stays a weak check; make it the AST: the keyword must appear in an `assert` statement or a `pytest.raises` argument of that test, not in a comment or docstring (ast.walk over the function, string constants and names only in assert nodes). Cost: ~25 lines.
3. Banned words: drop the whole-line exemption; use an explicit allow marker on the exempt line (`<!-- e-gate: allow reason -->`), and scan every tracked Markdown file under `docs/`, `services/*/README.md`, STATE.md, README.md, ROADMAP.md.
4. Commit check: `git show sha:path` parsed with `ast` and `name` looked up as a function, not a substring.
5. CI: a dedicated job with `fetch-depth: 0` and a first step that asserts `git rev-parse --is-shallow-repository` is false, so a shallow checkout reads as a configuration error, not a wall of "not an ancestor".
6. Pin the probe cases as `tools/tests/test_e_gate.py` (C-493 F-PR308-2 already asks for a failing fixture per check; the 19 cases here are a ready list).
