# C-443 reviewer (Lane 4): PR 285 @ac65009, claude-approver `_later`: a value that is not a time is never later than a real time (C-438; closes my C-437 F-C437-1)

VERDICT: PASS on ac650096f4ab61ea13ec699b38a5993ce2e7ac68. The cursor rule over `13:00Z`, `"not-a-time"`, `14:00Z`, `15:00Z` now ends on `15:00Z`; a real time is later than anything that is not one, in both argument orders, for strings, numbers, None, bytes and dates; same-type comparisons (two datetimes, two numbers) are unchanged; nothing I attacked raises. The 21 deleted lines are accounted for: the 13 of the old `_later` in `core.py` and 8 test lines, and the three tests that pinned the old "garbage is later" behaviour were rewritten to assert the opposite, not dropped. The whole claude-approver suite passes on the head (279). One narrower leftover (F-C443-1, LOW): when no real time has been seen yet, a value that is not a time still becomes the cursor and is sent.

## OBJECTIONS FIRST
1. F-C443-1 LOW (the cursor can still be garbage when nothing better is known): `_read_events` stores the first non-None `processed_at` as the cursor (`state.cursor is None`), parsable or not, and then sends it back as `created_at_gte`. A stream of only unparsable values leaves the cursor on `"not-a-time"` (probed: `["not-a-time", "also-bad"]` gives `"not-a-time"`), and `test_an_unparsable_cursor_is_replaced_by_the_first_real_time` pins that as "nothing better is known yet". The next real time replaces it; until then the list call carries a garbage filter. This needs the session's first events to carry no parsable `processed_at`, which the API does not do as far as I know. Cleaner: never store a value that is not a time (`_time_or_none(processed) is not None` at the assignment): the mutant that adds that check is KILLED only where the test asserts the garbage cursor, i.e. the two behaviours conflict, so it is a design choice for the builder, not a defect of this PR.
2. F-C443-2 LOW (same-type behaviour is claimed unchanged but pinned only for single digits): two numbers fall through to the direct `a > b`; the only number test is `_later(2, 1)` / `_later(1, 2)`. The mutant that replaces the direct comparison with text (`str(a) > str(b)`) survives the new file and the whole suite (279): `_later(10, 9)` would then be False. Today it is True (probed).
3. LOW (readings of "not a time"): a `date` object and an epoch number are not times for this function, so they lose to any real time and never replace a real cursor (probed: a numeric epoch cursor is replaced by an ISO string, an ISO cursor is not replaced by an epoch number); `2026-10-28T24:00:00Z` (a valid ISO midnight) is not parsed by Python and so counts as garbage. The API sends neither as far as I know.
4. EQUIVALENT survivors: `except Exception` for `(TypeError, ValueError)` in `_time_or_none`; the datetime-pair fast path (removing it or widening it to "either is a datetime": two datetimes then take the instant comparison, which gives the same answer; a datetime against a string raises `TypeError` and passes on); `>=` in the text fallback of two values with no common order.
