Reading: Caddy's `header` without `defer` runs BEFORE `reverse_proxy`, and the proxy ADDS the upstream's headers to what is already set, so the upstream value is delivered beside Caddy's, never instead of it. Whether it matters: for the two routes that exist today it does not (two `Cache-Control` lines combine to `no-store, no-cache`; the CSP is untouched because the console sends none). It would matter the day the console sent a policy header of its own: two CSPs are both enforced (safe), but for `Referrer-Policy` the browser takes the last recognised value (general knowledge, MEDIUM), so an upstream `unsafe-url` would have won. `defer` makes Caddy's block the last word on every route; `Content-Disposition` and `X-Accel-Buffering` still pass through. HIGH for the measured lines; the browser-side combination rules are not measured here.
