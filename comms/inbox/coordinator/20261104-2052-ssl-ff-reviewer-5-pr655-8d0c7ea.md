## Objections first
1. SILENT NORMALISATION OF AUTHORITY: scope entries are now stripped and de-duplicated before the token is minted, so the token's scope is not byte-for-byte the scope the caller asked for (`" read"` becomes `"read"`, `["a","b","a"]` becomes `["a","b"]`). Scope is matched by exact string downstream, so this widens what a padded request can match. Intended (the docstring says so, and mutant s1 is killed), but a caller that compares the minted scope to its request will see a difference, and a stored policy that expects a padded entry will no longer match. Not in source: whether any caller depends on the old behaviour. MEDIUM.
2. Dropping duplicates "keeping the first occurrence's place" is stated but only half pinned (s5 survives: which occurrence's place is kept is not tested).
3. The `/oauth/introspect` cap closes a memory pressure path but only on that route; every other body in the service is still read whole by the framework. LOW.
4. Cap values (100 entries, 200 characters, 16 KiB) are chosen, not derived; they are pinned exactly at the boundary (b1 to b4, o1, o2 killed), so any later change is visible. Accept.
