## Code read
- The 503 detail now carries one of four fixed categories (`sentinel unreachable`, `sentinel returned <3 digits>`, `... non-JSON body`, `... no verdict`) or `sentinel check failed`; the three fixed texts match the ones `SentinelClient.check` raises (api.py:366-376). The log keeps only the exception class.
- `anthropic-version` must be `YYYY-MM-DD` in ASCII digits (the value is forwarded with the real key, and a non-ASCII value used to raise inside httpx).
- `x-field-agent-id` and `x-field-token` must be 1 to 128 characters, one line, no character of Unicode category Cc, Cf, Zl or Zp, and no surrounding space; `x-field-action` is checked after `.strip()`, which is how the handler later uses it (api.py:939). An empty identity header stays the existing 401.
- The checks run at the top of the handler, before the enforce and passthrough logic, so in observer mode a malformed identity header is now a 422 instead of being forwarded (code read, not exercised). It is a client error and is documented in the README row (MEDIUM for the observer-mode effect).
- Unlike the check in PR 996, this one uses Unicode categories, so C1 controls (U+0085), U+2028/U+2029 and zero-width characters are refused. Measured by the tests for Cc and Cf; Zl and Zp are not tested (below).
