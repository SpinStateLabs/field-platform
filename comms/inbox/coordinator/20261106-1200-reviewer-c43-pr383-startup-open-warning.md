## OBJECTIONS FIRST
1. F-C43-1 MEDIUM-LOW (the "a value passed by mistake is dropped" guard is pinned on one side only; 5 of 45 mutants survive, 3 real): `startup._NAME` is `^[A-Z][A-Z0-9_]{0,63}$`. Mutants that drop the end anchor (S8: `^[A-Z][A-Z0-9_]{0,63}` then `.match`, so `SECRET key=abc` would pass as its prefix and be logged whole), that move the length bound to 65 or to 63 (S5, S6) all SURVIVE the 69 tests of the two new files. Probed on the real code: `lower_case`, `has space`, an 80-character name, a 65-character name, a non-string and a name with a newline are dropped; a 64-character name is kept; `SK_LIVE_ABC123` and `SECRETVALUE123` (a secret that happens to have the variable-name shape) ARE kept, which is by design and means the guard stops accidents that look like prose, not a secret that looks like a name. Today every caller passes a constant (`FORCE_GATEWAY_ENFORCE`, the two ledger flags), so no value can reach the line; the guard is for a future caller bug and should be pinned where it claims to act. Fix: three parametrised cases (a trailing space or newline after a valid prefix, a 64-character name kept, a 65-character name dropped). Real survivors: S5, S6, S8. Equivalent or cosmetic: S10 (the `isinstance(x, str)` check, since `str(x)` of a non-string cannot be upper-snake shaped in practice) and S18 (the wording "started OPEN (demo mode)" is not pinned: the tests assert the names, not the sentence).
2. F-C43-2 MEDIUM-LOW (a value echo next to the new line, not in it): with `FIELD_OPERATOR_REQUIRE` set to a made-up marker (a mistype) and no secret, starting any of the eight services with an operator layer printed `FIELD_OPERATOR_REQUIRE='<the marker>' is not one of 1/true/yes/on or 0/false/no/off; treated as ENFORCE (fail closed)`. That message comes from `operator_auth.mode()`, not from the PR's code; the PR's `open_settings` calls `mode()` for these services, so it now fires at startup instead of at the first guarded request. The PR's own line stays clean (it then lists only the secret, because a refused value is "enforce", not open), but the headline of the change is "never a value", and a mis-pasted secret in this variable would reach the log through the neighbouring message. Same class as the posture-flag echoes closed in C-502 and PR 352. Fix: have `mode()` name the variable without the value (and pin it), or have `open_settings` not trigger it.
3. F-C43-3 LOW (merge order): `git merge-tree` of the merged state with each other open PR: clean with PR 349, 369, 374, 375 and 325; CONFLICT in `docs/ENVIRONMENT.md` with PR 352 and with PR 381 (the first-read line citations moved by this PR's inserted lines). 4. LOW (what the line is, said honestly): it is a log line. Without any logging configuration Python's last-resort handler writes a WARNING to stderr, which is how my probe saw it; I did not run the services under uvicorn or under the compose stack, so how the line reaches `docker logs` is read, not measured. It also fires per process, so a multi-worker deployment prints it once per worker (the module says "per process").
5. LOW (scope): six services carry no operator layer (attestation-reporter, claude-approver, compliance-crosswalk, conformance-sentinel, force-gateway, incident-replay: grep finds no use of the operator-auth or health modules in their source) and the PR passes `operator_layer=False` for exactly those; the eight others pass True. Consistent with the code today; a service that gains an operator layer later has to remember the flag (the test table lists it per service, which would turn red on a new service call only if someone adds the service to the table).
6. NOT A DEFECT (probed): the line is once per service name per process (two creates, one line; 40 racing threads, one line); closed settings print nothing (all 14 services with the secret, operator, signing and enforce set); a junk `FORCE_GATEWAY_ENFORCE` makes the gateway's `create_app` raise `InvalidPostureFlag` exactly as before, with no startup line and no value; a whitespace-only secret is treated as set by the existing perimeter code and the line follows it; a service name with a newline would put a second line in the log, which only a caller bug can do (every call passes a literal); `warn_open` never raises (a forced error returns False, and the mutant that re-raises dies).
