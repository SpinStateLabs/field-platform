# C-234 reviewer (Lane 4): PR 113 test/operator-keygen-c191 @1f59f9e, operator_keygen pins for C-185

VERDICT: PASS on 1f59f9e8f718837d17d1b2aff87bb19781808307, with one real weakness (F-C234-1: the file-mode pin goes vacuous under a restrictive umask) and 3 LOW gaps. Every mutant the card names goes red under the usual umasks (0002, 0022). Tests only; no source change.

## OBJECTIONS FIRST
1. F-C234-1 MEDIUM-LOW (the question the card asked about vacuity): the mode test passes vacuously when the process umask clears the bits the mutant adds. `os.open(path, ..., 0o600)` is masked by the umask. Under `umask 0002` (this GX10) and `umask 0022` (GitHub runners) the five card mutants (0o644, 0o666, 0o777, 0o601, plus my 0o640) all die. Under `umask 077` all five SURVIVE with 15 passed (checked by running the same mutants under `bash -c "umask 077; pytest ..."`). `umask 077` is a normal setting in hardened shells and containers. The test never sets the umask itself, so its power depends on the environment. Fix: `old = os.umask(0)` inside the test (restore in a `finally`), so the mode the code asks for is the mode the file gets. The test is correctly skipped on Windows (`skipif os.name == "nt"`), so it is not vacuous there by accident, just absent.
2. F-C234-2 LOW: the mode check is `mode & 0o077 == 0` plus `mode & 0o600 == 0o600`. A file created 0o700 (owner execute) passes (mutant K06 survives the whole keygen suite). Harmless for the claim ("no group or other bits") but it is not "exactly 0o600"; `assert mode == 0o600` would be tighter.
3. F-C234-3 LOW: `--check FILE --scopes ""` (empty string) is not pinned. The guard is `a.scopes is not None`; changing it to a truthiness test (`or a.scopes`) passes all 74 keygen tests, so `--check` would then run silently ignoring an explicitly given empty `--scopes`.
4. Not a defect of this PR, found on the way (outside the card): the alias length boundary (`<= 128`, mutant `<= 127`) and the `.strip()` of each scope (`" kill"` with a space) are unpinned in the whole suite. Listed so they are not lost; no card from this PR.
