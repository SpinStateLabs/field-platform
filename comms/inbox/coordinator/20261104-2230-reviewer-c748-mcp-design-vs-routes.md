OBJECTIONS FIRST
1. One write route is missing from the route list: spend-governor `POST /escalations/{escalation_id}/resolve` exists in main (spend_governor/api.py:436-447, guarded by guard_escalation, binds the resolving operator) and is not in the prompt's spend-governor line (which lists GET /escalations only). The prompt says a coverage test fails on a route with no tool and no written exclusion, so the omission would be caught by the test, but the SCOPE and the tier text would be wrong until then. PROVEN.
2. A "read-only POST" in Tier 1 is not read-only: `POST /regwatch/check` (compliance-crosswalk) reads every cited source over the network and "a change SETS a stale flag" (compliance_crosswalk/api.py:155-163), i.e. it writes state and makes outbound fetches; that belongs in Tier 2 and needs the egress rules (no URL from a caller). PROVEN. `POST /check` (conformance-sentinel) is also listed as read-only; the repository's own integration text says every ALLOW it returns is metered to the governor as one action and shadows are ledgered (docs/INTEGRATION.md, the sentinel bullets), so a model calling it consumes budget and writes records; I could not find the metering in the service's api file (it is in the engine and clients), so this one is MEDIUM confidence from the doc, not from code. `POST /introspect` and `/oauth/introspect`, `/crosswalk`, `/crosswalk/markdown`, `/replay`, `/replay/markdown` I read as pure reads at the route level but did not trace to their clients.
3. A state change is tiered too low: `PATCH /agents/{id}` is Tier 2 in the prompt (PATCH is "state-changing"), but a status change through it is a kill, revive or decommission performed "by another" party (agent_registry/api.py:257-265, mapped to those three actions). That is Tier 3 (destructive) in the prompt's own words ("kill, ... revive"). PROVEN by reading. Likewise `POST /spend` and `POST /usage` (spend-governor) let a caller write the meter: a false usage report changes caps and escalations; the prompt tiers them only as generic state changes, and `POST /events` (sealed-ledger) appends audit records, which in a platform whose value is the audit trail deserves Tier 3 and a named control. MEDIUM.
4. Tier 3 omits `claude-approver POST /halt/{id}` (a halt of an agent), `POST /escalations/{id}/resolve` (above), agent PATCH with status (above), and `POST /agents/{id}/attest` / `/discover` (registry state). The Tier 3 list in the prompt names kill, kill/domain, revive, fleet halt, token issue and revoke, rotate, hold and release, retention/apply, caps, policies, rate-limits, federation contract changes. HIGH for the halt and resolve omissions.
5. A tier the prompt does not name: the operator identity pair. Eight services import the operator-authority layer (agent-registry, delegation-authority, federation-broker, kill-switch, lifecycle-manager, ops-console, sealed-ledger, spend-governor), and guarded writes need a human operator id and key in addition to the perimeter secret. The credential decision ("one key per service, scoped per tier") names the perimeter key only. Who holds the operator key under stdio, and why a model must never hold it, is the confirmation question the prompt asks for Tier 3, but the credential section does not name it as a separate secret class. MEDIUM-HIGH.
6. Hidden routes: field-core installs `POST /operator/verify-hash` and `GET /operator/rotation-state` on every service where the layer is armed with a perimeter secret, registered with include_in_schema False (operator_health.py:710). A coverage test that enumerates the OpenAPI schema will not see them; one that enumerates registered routes will, and then needs a written exclusion (the first is a hash oracle; see my PR 351 and PR 349 reports). The prompt does not list or exclude them. PROVEN for the registration.
7. Streaming and HTML routes: ops-console `GET /api/stream` is a server-sent-event stream (ops_console/api.py:448) and `GET /` returns the console page; neither fits a request/response tool. The prompt says the designer decides between console and services; it does not say what happens to these two. LOW.
8. The prompt lists attestation-reporter `GET /pack` as a plain read; the sequence diagram and attest verbs imply a render that may ledger; I did not check whether serving the pack writes a record. NOT VERIFIED.
