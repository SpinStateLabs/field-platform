## OBJECTIONS FIRST
1. F-C645-1 MEDIUM-LOW (the redirect pin is only tested with GET, and `send` forwarding is not tested): on both PRs the mutant `if request.method == "GET": kwargs["follow_redirects"] = False` SURVIVES all 229 (PR 318) and 248 (PR 330) lifecycle-manager tests; so does `super().send(request, follow_redirects=False)` (drops every other keyword, `stream` and `auth` included) and the mutant that pops `stream` from the keywords. The code is right today (probed: a POST with `follow_redirects=True` and a 307 to another host stops at the first response). Pin: a 307 and a 308 for POST, PUT and DELETE; a streamed response is actually streamed; an `auth=` argument still reaches the request.
2. F-C645-2 LOW (one path is not pinned): `client.send(request)` with NO keyword after `client.follow_redirects = True`. The mutant that forces the flag only "if the caller passed it" survives (for `get` and `request` httpx always passes the flag, `USE_CLIENT_DEFAULT`, so those paths are covered; a direct `send(req)` with no flag is the one that reads the attribute). Add that case.
3. LOW (deliberate bypass, out of scope and stated): calling the base class explicitly (`httpx.Client.send(client, request, follow_redirects=True)`) or a subclass that does so follows the redirect. The class cannot stop a caller that skips it; a subclass that passes `follow_redirects=` to `super().send` gets a `TypeError` (the override already sets it), not a silent follow. Nothing in the repository does either (`git grep follow_redirects` in `services/lifecycle-manager/src` finds only the two pins).
4. LOW (carried from C-569, unchanged): the CLI's `_service_client` in lifecycle-manager is a plain `httpx.Client` on the C-57 proxy allowlist; it does not follow redirects (the httpx default) but reads the proxy environment. Not this change.
