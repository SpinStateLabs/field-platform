2. The federated rule is not deduplicated: on this head a non-isolated manifest with an empty `allowed_peers` returns BOTH the targeted line and a `schema violation — federated: Value error, ...` line (probed). The schema error's path is `federated`, which is not under the registered `federated.allowed_peers` (nor `federated.isolated`), so `named.add("federated.allowed_peers")` has no effect that I could find: a one-line dead addition, and the "already named" duplicate the PR set out to remove is still there for this rule. MEDIUM-LOW (HIGH confidence on the probe; the intent of the line I do not know).
3. The impossible-expiry result is a warning, so the manifest still reads as valid-with-a-warning; the PR states this is the owner's call (code comment). Accepted, but a caller that gates only on `critical` will pass a manifest whose expiry cannot be read. LOW-MEDIUM.
