## Design (my choices, the card left them open)
1. `FIELD_SHARED_SECRET` stays the full (write) key. New optional `FIELD_READ_KEY`; `FIELD_READ_KEY_<SERVICE>` (upper-case, dashes to underscores) replaces it for one service when `install(app, service="...")` is given a service; the generic key is then NOT a fallback.
2. A read key is accepted only on GET, HEAD, OPTIONS and only on paths not in the new `write_only_paths` argument. A GET that changes state must be listed there: the middleware sees the method only. I did not audit the 13 services for state-changing GETs (the MCP design note says `/check` and `/regwatch/check` are such); that is the follow-up before any service sets a read key.
3. Fail closed: read key set with no full key refuses every non-safe request (a read key never turns the open demo mode into an open write path). A read key equal to the full key raises `TierKeyError` at install, fixed text, no key in it. After install an equal key is ignored.
4. Refusals are the same 401 and text for any bad key, including a valid read key used on a write (no oracle for the read key). The module has no logging; a test slices every key into 8-character windows and finds none in any refusal body, header or log record.
5. `read_auth_headers(service)` returns the read key header only (never the full key or the operator pair), for the read-only MCP process.
6. Comparison now encodes to bytes before `hmac.compare_digest`: a non-ASCII header made the old code raise TypeError (500). Side effect on existing behaviour: such a header is now a 401. I did not add a test for the old crash.
