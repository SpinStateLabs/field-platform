OBJECTIONS FIRST
1. "An upstream reply body is never part of an error message" is a claim about every path a body can take to an exception; the PR fixes the `resp.text` paths. The body can also arrive through a validation error, through a CLI's own error line and through a repr of an upstream value.
2. A DEBUG record that holds the body is the same leak one switch away; "DEBUG is not on by default" is a deployment fact, not a code property.
3. A helper that formats one status code is only as good as the places that call it; the sites that do not call it are the finding.
