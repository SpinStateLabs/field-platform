## OBJECTIONS FIRST

1. PR 414 is a CI gate whose acceptance statement is wider than its behaviour. The note, the module docstring (tools/vulture_gate.py:3-4) and the ci.yml step comment all say it fails on "an unused import, unused variable or function, or unreachable code". At `--min-confidence 80` vulture reports unused imports (90), unused function ARGUMENTS and unreachable code (100). It does NOT report an unused function, class, method, attribute or local variable (60). Measured, below. A reader of the CI comment believes a new dead function is blocked; it is not. (F-Q43-1)
2. A gate is only as good as the exit code CI reads. Nothing in the 12 tests runs `main()` or the CLI, so `return rc` -> `return 0` in main() survives all of them (G08). The branch that says "vulture did not run" (exit 2) is also unpinned (G10). Both are fail-closed today; neither is held. (F-Q43-2)
3. The CI step itself can be neutered without any test going red: `continue-on-error: true` (C03) or an `if:` that skips it on pull_request (C04). The wiring tests read only the step's `run:` text. (F-Q43-3)
4. PR 413 renames two hooks that a process-global state reset depends on. The new pin for the operator_auth side asserts only that the counter returns to 0; it would not notice a reset that stopped clearing `_retired_seen` (A07). That body is unchanged by the PR, so this is a pre-existing gap, but the PR's own note says "the operator_auth side was not mutant-tested", and the PR's own pin is the place that would hold it. (F-Q39-1)
5. PR 412's guard test is stronger than main's, but `is_guarded` still judges a different string than the sender sends for two shapes (`//host/delegation/tokens`, `scheme://host/...`). Unreachable today (every call site passes a literal or a validated UUID); recorded so a future caller does not meet it cold. (F-Q38-1)
6. All three PRs were written and tested by the same builder lane that wrote the note; no mutant here is theirs. I ran my own.

Steelman for the opposite case: B-15 and B-10 are one-file and two-line changes with a green whole-suite run and a repo-wide grep behind them; B-11 adds a real, pinned, fail-closed gate where there was none, its allowlist is exact and cannot rot, and the gate is clean on the shipped tree. The conditions on PR 414 are about wording and four unpinned branches, not about the gate being wrong on what it does check.
