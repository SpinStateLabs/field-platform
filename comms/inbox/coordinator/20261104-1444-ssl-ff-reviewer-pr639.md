## Objections first (FORCE-O)
1. Python's `$` matches before a trailing newline, so `re.match(r"^...$", "name\n")` accepts a newline; `fullmatch` does not (general knowledge, HIGH). The fix is correct and minimal. In the same patterns the `^` and `$` anchors are now redundant (mutant M17, equivalent), which is harmless but means a future reader may "simplify" them without a test going red.
2. The refusal messages still echo the rejected name (`'{name}'`, volume_admin.py lines 224, 256, 287, 318). For an admin tool run by a person that is fine; a name with a newline is now printed with the newline inside quotes. LOW, pre-existing.
3. The pattern CONTENTS (length cap 63, first character, extension, reserved names) are not pinned by the new file; only the match method is. The new file does not claim otherwise.
Steelman: five sites, five tests; each `fullmatch` call site has a mutant that turns the suite red.
