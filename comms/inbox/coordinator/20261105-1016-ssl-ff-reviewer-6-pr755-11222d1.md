## Objections first (FORCE-O)
1. The two creation paths give different file modes. Measured on the head: the sentinel created by the new hard-link path has mode 0600 (the temp file comes from `mkstemp`, and a hard link keeps the inode's mode); the old `_write_atomic` also produced 0600, so the common path is unchanged, but the new fallback (`O_EXCL` create where hard links are unsupported) makes the file 0644. If another account reads the sentinel (the gateway or the kill-switch under a different user), the answer depends on which path the filesystem allowed. Not tested (the tests check content and absence of the temp file, not the mode). LOW.
2. Hard-link-then-unlink is exclusive (a human's file wins) and atomic (no reader sees a partial file); the test that simulates the race (the existence check patched to return False while a human file exists) proves the human's bytes survive and no temp file is left, in both the link path and the no-link fallback. One residual: `os.link` and `O_EXCL` both refuse to replace, but neither protects a human who creates the file between the link failure and the fallback; the fallback then also fails with FileExistsError and returns False, so the human's file still wins (read, not tested).
3. Mutant K12 (the temp file is not fsynced before the link) survives; durability of the sentinel's bytes is untested (the same gap as PRs 645 and 725). K7 survives and is equivalent: a FileExistsError from `os.link` not handled by its own clause is caught by the `except OSError` that follows (FileExistsError is an OSError) and the fallback's `O_EXCL` then refuses to replace it, giving the same answer.
4. The BOM change is correct and tested: `utf-8-sig` strips a leading BOM; with plain `utf-8` five tests fail (measured; my first batch run did not match that line, so I ran this mutant by a one-line `sed` and report the result of that run). Every other refusal (whitespace, control, non-ASCII, empty, unreadable) is kept; a BOM-only file is "empty".
Steelman: a kill must never replace a sentinel a human created in the window between `exists()` and the create (the old `os.replace` clobbered it, which would also let a later revive remove the human's halt); and a secret file written by Windows PowerShell 5.1 (UTF-8 with BOM) made the watcher refuse a valid secret, unlike estate_probe, renew_token and provision_ssl_agents, which already read it.
