## Objections first (the strongest cases against passing this PR)

1. **The rule is character classes, not "a plain human".** "svc-ledger-writer", "agent-7f3a9c" and a token-shaped string are all accepted. A reviewer could say the finding's title ("names a plain human") is not met. Answer: the finding's kill test asked for parity with `_named_human` ("refuses control, invisible or no-alnum names"), and no character rule can tell a person from a machine id. I treat this as by design (F-Q58-5, INFO), not a defect of this PR.
2. **A "name you can SEE on one line" still admits an invisible name.** U+3164, U+115F, U+1160 and U+FFA0 (Hangul filler letters, category Lo, `isalnum()` true) pass alone. The hole is in the rule the PR copies, so the PR is consistent with `check-file`, but the human gate is weaker than its docstring says (F-Q58-2, LOW).
3. **The PR's rule omits `Cs`, and PR 419 (open) refuses it.** A lone surrogate passes the rule and the write then crashes with `UnicodeEncodeError`. The file is intact (fail-closed on disk) but the gate ends in a crash, not a named refusal (F-Q58-1, LOW). The same class was F-Q47-3 on PR 419, which fixed it in `textsafe.py`.
4. **The no-echo test is weak.** It covers one branch with a two-letter marker ("Do"); mutants that echo the name in the other two refusal branches survive the PR's tests (M19b, M19c).
5. **No cap.** A 1 MiB name is accepted and persisted (F-Q58-3, LOW).

None of these makes the clear unsafe: no refusal path writes anything, none echoes the text, and nothing is reachable over HTTP. They are proposed builder cards.

3. **The rule equals `_named_human`.** Differential over all 1,114,112 code points in three shapes ("A?B", "?A", "A?") between `_plain_reviewer_name` and `regwatch._named_human`: 0 disagreements. `regwatch._CONTROL_CHARS` ([\x00-\x1f\x7f]) is a subset of category Cc, so the regex adds nothing. 4. **Fail-closed.** The check runs before `with self.transaction()` (staleness.py `clear`), so a refused name never reaches the pop or the persist. Mutant M16 (validate after the pop) is killed by the PR's "clears nothing" test on the same object; M16b (validate inside the transaction, before the pop) is equivalent (no persist, reload on the next transaction). 5. **No echo.** The three ValueError messages are fixed strings (no `name` interpolation). Real CLI process (entry `crosswalk = compliance_crosswalk.cli:app`), refused names with a marker string: stdout+stderr do not contain the marker, the traceback shows no locals table. The only `log.` call in `staleness.py` (line 126) logs the lock path. There is no HTTP route that reaches `StaleStore.clear`: `api.py` routes are /health, /frameworks, /controls, POST /crosswalk, POST /crosswalk/markdown, GET /staleness, POST /regwatch/check, POST /pack, and `.clear(` is called only at cli.py:341 (README :207-211 says the same). So the "HTTP route" probe is not applicable; `GET /staleness` only READS the stored history (JSON-escaped).
6. **Other clear paths unchanged.** Missing flag: `KeyError(framework)` (inside the transaction, after the name check, same order as before). Already cleared: the flag is gone, so `KeyError`. Concurrency: the transaction is unchanged (thread lock, OS file lock, reload, persist only if the body did not raise).
7. **What the rule admits (probes, made-up names).** Accepted: digits only, one letter, a Cyrillic-lookalike name, an NFD (combining mark) name, a private-use character inside a name, "svc-ledger-writer", "agent-7f3a9c", a token-shaped string, a 1 MiB name. Refused: U+2800 alone (no alnum), every Cc/Cf/Zl/Zp character, "..." and blank. Accepted and invisible: U+3164, U+115F, U+1160, U+FFA0 alone.
8. **Lone surrogate.** "Don" plus U+D800 passes the rule; `_persist` writes JSON with `ensure_ascii=False` as UTF-8 and raises `UnicodeEncodeError` inside the transaction. Result: the file bytes are unchanged and the temp file is unlinked (atomic), the flag is still active after reload, history is empty. But the same in-process object is left with `active() == []` and one history record until the next transaction reloads the file. In the CLI (a fresh process per command) this is harmless; in a long-lived caller it is a stale view.
9. **Comparison with PR 419.** 419 adds `textsafe.REFUSED_CATEGORIES = {Cc, Cf, Zl, Zp, Cs}` and caps rendered text at 300 characters. 422 does not import it (419 is unmerged), keeps its own copy of the regwatch category set, and so diverges on `Cs` and on the cap. After both land there will be three copies (regwatch.py:523, the new staleness constant, textsafe.py).

## Findings (file:line, class, confidence; each with the one-line test that kills it)

All severities are mine; every item below is a proposed builder card, not code.

- **F-Q58-1 (LOW, HIGH confidence, PROBED).** `staleness.py` new constant `_REFUSED_NAME_CATEGORIES` (after `affected_controls`) omits `Cs`: a lone surrogate passes `_plain_reviewer_name` and `clear` ends in `UnicodeEncodeError` at persist, not a named refusal; the in-process store shows the flag cleared until the next transaction. Fix: add "Cs". Kill test: `clear(FW, "Don" + "\ud800")` raises ValueError and `active()` still lists the framework. (Fails on the head, passes with the fix; mutant M08 shows no test pins Cs either way.)
- **F-Q58-2 (LOW, HIGH, PROBED).** Same constant plus the `isalnum()` rule: U+3164, U+115F, U+1160, U+FFA0 alone are accepted (invisible name). Same hole in `regwatch._named_human`. Fix: count only an alnum character that is not a filler (`"FILLER" not in unicodedata.name(ch, "")`). Kill test: parametrize those four code points into REFUSED. Verified in a scratch tree: adding "Cs" plus the filler rule gives 62 passed (the PR's 47 plus 15 proposed tests).
- **F-Q58-3 (LOW, HIGH, PROBED).** No length cap in `_plain_reviewer_name`: a 1,048,576-character name is accepted and persisted (store file 1,048,989 bytes) and is returned by `GET /staleness` history. PR 419 caps rendering at 300 but the store keeps everything. Kill test: a 201-character name is refused (cap value chosen by the builder).
- **F-Q58-4 (LOW, HIGH, PROBED).** cli.py:336-343 (`regwatch clear`) does not catch the ValueError: a refused name prints a Rich traceback (3,375 bytes in my probe), exit 1, where `check-file` prints `REFUSED (nothing written): ...` and exits 2 (cli.py:286-288). The PR's CLI test asserts only `exit_code != 0`. An unknown framework is the same (pre-existing KeyError traceback). Kill test: the CLI exit code and message for a refused name equal the check-file convention.
- **F-Q58-5 (INFO).** Service-id and token-shaped names are accepted by design (objection 1). A secret pasted as `--reviewed-by` would be stored and served by `GET /staleness`; operator error, no code defence possible short of a length and shape rule.
- **F-Q58-6 (INFO).** README.md:209-211 and :276 say the clear "requires --reviewed-by" without stating the plain-name rule; the PR changes two files and no docs.
- **F-Q58-7 (INFO).** The test source holds literal U+200B, U+2028, U+2029, U+202E (bidirectional override) and U+FEFF characters (`REFUSED` list). Use `\u` escapes: a literal bidi override in a committed file is the "Trojan source" class and invisible in review.
- **F-Q58-8 (INFO).** Three copies of the category set after 419 lands; one shared constant would stop the drift that F-Q58-1 shows.
- **F-Q58-9 (INFO).** Records cleared before this fix are not migrated; `GET /staleness` serves them JSON-escaped (no injection on that route).
