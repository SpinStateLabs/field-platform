## OBJECTIONS FIRST
1. F-C729-1 MEDIUM-LOW (a 200 or 201 reply with a JSON body of the wrong shape leaks its start): the SDK sites build a model from `resp.json()` after the status check. A body that is a JSON list or string makes pydantic raise `ValidationError` whose message prints `input_value=...` (the first characters of the body). Probed with the marker plus 5,000 characters: `LivenessClient.heartbeat` and `.checkin` (200), `UsageClient.report` and `.spend` (201): for a JSON list body and a JSON string body the marker IS in the exception text and in the traceback (8 of 8 cases); for an object body (`{"detail": ...}` or wrong field types) it is not (the model hides the input), and a non-JSON body gives `JSONDecodeError` without it. `bootstrap.mint` does the same (`DelegationToken.model_validate(resp.json())` after a 201); I did not probe it. A service on the trust boundary answering 200 with a list or a string is rare, but the PR's own rule is that an upstream reply "can quote a value the caller sent". Fix: catch `ValidationError` and `ValueError` at those sites, raise a fixed message (`... returned an unreadable reply`) `from None`, and pin it with a list and a string body.
2. F-C729-2 LOW-MEDIUM (same class, outside this PR, so not a defect of it): in `lifecycle_manager/engine.py`, the step detail of a failed token listing is `f"could not list tokens: {listing.text}"` (line 1063: the response body for a real non-200 reply) and `_Unreachable.text` is `f"transport error: {type(exc).__name__}: {exc}"` (the transport exception's own message), both returned in the transition report; the CLIs of delegation-authority, kill-switch, spend-governor, federation-broker, incident-replay and conformance-sentinel print `resp.text` or `resp.json().get("detail")` to the operator (operator-facing output, a different threat model, but the same body); `field_core.clients` and `bootstrap` still put `str(exc)` of a transport error into their messages (`LedgerUnreachableError(str(exc))`, `BootstrapError(f"agent-registry unreachable: {exc}")`). None is a regression; list them so "an upstream body is never part of an error message" is not read as repository-wide.
