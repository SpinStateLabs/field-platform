## DECISION FOR DON (deploy risk)
The rule is by scope set (the card text and the runbook check), not by lookalike id. A registry load failure is fail-closed: every service that loads the file answers 503. Five test fixtures listed the full set explicitly on the human row `don`, which suggests the real operators file might too; the runbook says human rows hold `*`. I did not and cannot check the real file (public repo). Run the runbook's D-18 snippet on the file before installing a build with this change. Alternative if Don prefers a smaller blast radius: refuse only ids containing "verif" in any case that lack the exact prefix; that would leave other-named rows unbound (still caught by the runbook check).

## Not covered (stated)

- An alias (`names`) that looks like a verifier.
- A `*` row (human rows).
- Revoked rows are not refused (they cannot authenticate).
