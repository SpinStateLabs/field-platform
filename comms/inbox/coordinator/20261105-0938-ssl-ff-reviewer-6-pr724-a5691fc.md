## Objections first (FORCE-O)
1. `_usable_dir` creates the directory as a side effect of checking it (`mkdir(parents=True, exist_ok=True)`). A `--journal-dir` that does not exist is created before the simulation runs; that is also what `run` needs, but a refused `--journal-dir` under an existing parent can leave behind newly created empty parents (not tested; LOW).
2. The permission half of the check cannot be tested where this was run: the unwritable-directory test skips under root (`os.access` is True), so the write-bit and exec-bit conditions (mutants D8, D9, D7) survive the file here and are not exercised. They would be killed by a non-root run, which CI may do (not verified). The behaviour for a regular file, a path under a file and a NUL byte is tested (D10, D11 killed).
2b. Mutant D6 (`is_dir()` not required) is equivalent: if a regular file is in the way, `mkdir(exist_ok=True)` already raises (caught as OSError), so the later `is_dir()` never sees a file.
3. The CLI de-duplicates targets by exact string (`dict.fromkeys`); `fly-app-a` and `Fly-App-A` or a trailing space stay distinct, so "repeated" means "byte-identical" (tested only for identical strings; LOW).
4. In `run`, the journal-dir check happens only after the "no --target" early return, so `run --journal-dir <a file>` with no target still exits 0 (tested and stated as unchanged; D5 killed).
Steelman: before the change `--journal-dir` naming a regular file, a path under one, a NUL byte or an unwritable directory ended in a FileExistsError, NotADirectoryError or PermissionError traceback, and `--target x --target x` seeded and rotated the same target twice (a repeated target meant two simulated rotations and two planned journal states). Now the first is one `refused:` line with exit 2 and nothing simulated, and the second runs once, in first-occurrence order.
