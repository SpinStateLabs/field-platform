## OBJECTIONS FIRST
1. F-C663-1 MEDIUM-LOW (the one part of the URL that is shown is not checked): `public_origin` prints `parts.hostname`, which for a URL like `http://host.example <text>` is the whole authority, so everything between `://` and the first `/`, `?`, `#`, `@` or a port colon is shown (lower-cased). Probed with a made-up canary: `http://host.example <canary>`, `http://host.example;<canary>`, `http://host.example,<canary>`, `http://host.example key=<canary>`, `http://host.example%2F<canary>` all print the canary in `/health` form; a canary as the host (`https://<canary>`) or as the scheme (`<canary>://h`) prints too (by design: those are the shown parts). A value that has no scheme (the canary alone, `//<canary>`, `http:<canary>`) and a bad port (`http://host:<canary>`) correctly show the fixed word. The realistic slip is a secret typed after the host in a compose line (a space, a semicolon, a comma). Fix: accept the host only if it matches a hostname or IP pattern (letters, digits, `.`, `-`, `_`, or a bracketed IPv6 literal) and the scheme only if it is `http` or `https`; otherwise the fixed word. The mutant that removes the host check (`not host`) also survives the tests (it would print `http://None`), so that branch is not pinned either.
2. F-C663-2 MEDIUM-LOW (a documented behaviour that does not exist): the PR rewrites six ENVIRONMENT.md rows to say a non-number "raises InvalidNumericSetting (a ValueError naming only the variable, never the value)". Five are force-gateway and correct. The sixth is `FIELD_CONSOLE_MAX_STREAMS` (ops-console, `ops_console/api.py:364`), whose code is NOT in this diff: it is still a bare `int(os.environ.get(...))`. Probed on the merged state with a canary: it raises a plain `ValueError` whose text and traceback both contain the canary. `test_environment_doc` is green because it checks the cited line, not the sentence. Either change ops-console in the same PR (or the next) or revert that row. A grep for `int(os.environ` and `float(os.environ` in `src` finds the same cast form in `sealed_ledger/store.py` and `field_agent/canary.py` (`FIELD_CANARY_PORT`, `FIELD_CANARY_WORK_EVERY`, which ENVIRONMENT.md says "raises ValueError at start") as well as ops-console; I did not check each for a handler, so only ops-console is confirmed to echo.
3. F-C663-3 LOW (the original text still hangs off the transport error): `raise SentinelUnavailable(...) from exc` keeps the httpx error as `__cause__`. `str(exc)`, `repr`, `args` are clean, but `traceback.format_exception` includes the cause: for a URL whose port is not a number the cause message (httpx `InvalidURL`) echoes the port text, so a traceback logged with `exc_info` would print it (probed: traceback leak true for that URL, false for connection errors). Nothing in the gateway logs the traceback today (the two handlers turn it into a refusal), so this is unreachable now; `from None` (or `from type(exc)`) closes it. The mutant that removes `from exc` survives, so nothing pins either choice.
4. LOW (numeric values the parser accepts; behaviour carried, not introduced): `nan`, `inf`, `1e999` and a negative number are accepted for `FORCE_GATEWAY_LATENCY_BUDGET_MS` (a `nan` or `inf` budget can never be exceeded, which silently turns the latency fail-safe off); `FORCE_HYGIENE_WINDOW` of 0 or -1 and a negative `FORCE_GATEWAY_BYPASS_COOLDOWN` are accepted; `FORCE_HYGIENE_BASELINE_WINDOWS=0` too. A blank value (a compose `${X:-}`) raises `InvalidNumericSetting` at start, while the sibling tunables (`SAMPLE_EVERY`, `TELEMETRY_WINDOW`) treat blank as the default. A value over 4300 digits is refused by Python's own limit and reaches the same clean error. Out of scope of the card (it is about echo); noted for a validation card.
5. LOW (pins): the exception-type name in the transport message is not pinned (mutant `no type` survives); otherwise the PR's tests are tight.
