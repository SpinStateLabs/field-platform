## Objections first (FORCE-O)
1. The error line for an unreachable broker prints `_base()`, which is `FIELD_FEDERATION_URL` as set. Measured on the head: with `FIELD_FEDERATION_URL=http://user:PWD-MARK@127.0.0.1:1` the line is `error: broker unreachable at http://user:PWD-MARK@127.0.0.1:1 (ConnectError)`, so URL userinfo reaches stderr. The module's own rule ("callers pass only fixed text and exception TYPE names: never key or file content") is about key and file content; a URL credential is neither, but it is the same class of leak I measured in PR 638 (witness.py). LOW: the value is the operator's own environment variable on their own terminal. Strip userinfo before printing (not done here).
2. The no-echo rule for `sign` is only half pinned: mutant G7 (message echoes the exception text instead of the type name) survives the PR's file and the whole federation-broker suite (203 passed). The garbage-key test only proves SYNTHETIC-KEY-TEXT-MARK is absent, but with this environment's cryptography the load error text is generic ("Unable to load PEM file...", measured: the mark is not in str(e)), so the echo would not show. A library whose message quotes the PEM would leak while the test stays green. LOW; the code as written (type name only) is correct.
3. The tests cannot tell stdout from stderr: CliRunner mixes the streams in `result.output`, so mutant G13 (`_die` writes to stdout) survives the file and the suite. The module docstring and test title promise "one stderr line". LOW.
4. The outbound branch is untested end to end: G12 (outbound manifest bypasses the new `_manifest` wrapper) survives, because the CLI default is `--direction inbound` and every test uses it. LOW.
Steelman: before the change a missing manifest, a YAML list, a non-ASCII or public key, or a refused connection produced a traceback (and a key reason that can quote key material); now each is one line and exit 1, with the error text withheld. Other exception types (e.g. `httpx.InvalidURL`) still fall through the `_TRANSPORT_ERRORS` filter in principle, but I tried `http://[bad`, `ftp://x` and a refused port: all gave exit 1 with one line (measured).
