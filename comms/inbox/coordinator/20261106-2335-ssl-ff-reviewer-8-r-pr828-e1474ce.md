## Conditions
### C1 (MEDIUM, rollout): no service on this head passes `write_only_paths` or `service=`
Every `authn.install(app ...)` call site (16 services, my grep) uses the default. The read tier is off until `FIELD_READ_KEY` is set, but a generic `FIELD_READ_KEY` set in one environment would then apply to every service with an EMPTY write-only list, so any GET that changes state, or that returns something an operator would not hand to a read key, becomes reachable with it. A heuristic scan of the services' GET handlers for mutating calls found none (LOW confidence: pattern match, not an audit; hits were list appends and a CSV writer). Before any deployment sets a read key: one card to audit each service's GET routes, pass `write_only_paths` and `service=` where needed, and add a test per service that a read key is refused on its write-like GETs.
