## OBJECTIONS FIRST
1. F-C413-1 LOW (the fallback orders wrongly inside one calendar day, and the test names claim more than they show): `_later` falls back to `str(a) > str(b)` when the two values are of different types. `str(datetime)` uses a space between date and time, an ISO string uses `T`, and `T` sorts after the space, so within one date the string always "wins". Probed on the head: `_later("2026-10-28T01:00:00+00:00", datetime(2026,10,28,12,0,tzinfo=utc))` is True (an earlier string is called later) and `_later(datetime 12:00, "2026-10-28T23:00:00+00:00")` is False (a later string is called earlier). So a cursor that is a datetime can be moved BACK by an earlier string time on the same day. `test_a_mixed_type_cursor_never_moves_back` and the other two mixed-type tests use values a year or a day apart, which hides it. In production the SDK returns datetimes for every event, so mixed types arise only from a fake or a changed client; I do not know of a path. Production behaviour, not part of this PR; the tests should not claim "never moves back" for mixed types, or the fallback should parse the string.
2. LOW (alive mutants outside the card's brief; each survives the new file, and I ran them against the whole approver suite too):
   - `last_read` kept at its first value instead of updated on every read (`state.last_read or now`): survives all 221 tests. After the first read the shortcut would then compare against a stale time, so a long-running session would re-read on every tick (more API calls, not a missed ask).
   - `last_read` set before the read instead of after: survives (equivalent in effect: a failed read leaves `updated_at` unset, so the shortcut stays off).
   - the failed `events.list` branch no longer returning 0 (the tick would go on with stale state): survives; no test makes `events.list` fail.
   - `EVENTS_REFRESH_SECONDS` of 1 s instead of 60 s: survives (the boundary tests sit at 60 s and far above; nothing checks "30 s later still skips").
3. EQUIVALENT: `last_read` truthiness instead of `is not None` (differs only if the clock returns exactly 0.0); `_later` with `>=` (an equal time sets the cursor to the same value), also with the string fallback `>=`.
