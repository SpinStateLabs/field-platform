So F-C458-1 is closed here on (a) the author's recorded table in note 20261101-0905-builder-lane12-c1025-pr316.md, (b) general knowledge of the Caddy `header` directive (`defer` applies the operations when the response header is written, after the upstream reply; MEDIUM-HIGH) and (c) pins I mutated. Not on a run of mine.
2. `defer` changes what happens when no upstream reply is written. Caddy installs the deferred operations on a wrapped response writer inside the handler; an error response written by the server (console down, upstream timeout) does not go through that wrapper (MEDIUM, from the structure of Caddy's headers handler; NOT measured). Before this push the five headers were set on the response writer first and so could also appear on such a response. Consequence is small (the 502 body is Caddy's, no console content), but it is a behaviour change the PR does not name. F-Q53-1.
3. The test pins the TEXT of the block (the word `defer` inside the console header block, five exact header lines, the policy value). It cannot say what Caddy does; a Caddy upgrade that changed `defer` semantics would pass every test here.
4. `script-src 'unsafe-inline'` stays, so an injected inline script still runs; the policy only narrows where data can go (the file's own docstring says "narrows, does not close"). Pre-existing and named, not a finding of this push.
