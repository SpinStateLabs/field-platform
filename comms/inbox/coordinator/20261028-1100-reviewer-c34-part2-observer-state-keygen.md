## Findings
1. MEDIUM, PROVEN (probe on the GX10, ~/ff-work/probe57, no network): the independent witness cannot see a content-only edit. `OperatorObserver._observe_self_witness` decides "changed" from key = (format, generation, per-row (operator_id, status, current_fp, next_fp), sealed_state) (operator_observer.py, `key = (fmt, gen, tuple(...), sealed_state)`); `registry_sha256_prefix` is in the payload but NOT in the key, and scopes, names, event_prefixes, auth, rotation and `key_not_after` are not witnessed at all. Probe: first tick -> 1 `operator.registry_slots_changed`; a witness with a new file sha but the same generation and fingerprints -> still 1 (no event); a generation bump -> 2. So a hand edit that grants `*`, extends an expiry or changes `auth` without bumping the generation or touching a key slot is invisible to the ledger. A hand edit that does bump the generation is visible but the event does not say what changed. Fix: include the file sha prefix (or roster digest `operator_roster_sha16`, already computed in rotation_state) in the change key, and ledger it. I do not know whether R6 (`rotation_audit`) is meant to cover this; as merged, nothing does. Ties to #57 finding C-16 (2): with the rotator's own status file deleted the rotator also stops flagging foreign edits, so both detectors are blind to the same edit.
2. LOW (declared): the observer's memory is per process. After a ledger restart `_generation` and `_slots` are empty, so a generation decrease or a break-glass key change that happened while the ledger was down is recorded as `startup: true` / `sealed_key_changed: false`. Same pattern for the break-glass counters (`previous_bg is None`). State it in the runbook.
3. LOW: `MAX_WITNESS_ROWS = 256` (operator_observer.py): rows beyond 256 are silently dropped from the witness (no counter, no marker). Not reachable at the current 10-11 rows.
4. LOW (inconsistency, rotation-state masks, keygen does not): `operator_keygen.py` `--check` on a format 2 file prints `fingerprint {r['key_sha256'][:8]}` for EVERY row including the sealed break-glass row (`_print_format2`: "current fingerprint ... no expiry (sealed)"). rotation_state, verify-hash and the witness all print `(sealed)` and rotation_events/`slot_witness` document that "no prefix of it is ever written" because a hash prefix lets a holder of a candidate key test it offline (design S8). The CLI needs read access to the file anyway (which holds the full hash), so this is not an escalation, but it is the one place where the sealed prefix leaves the file, and `--check` output gets pasted into tickets and logs. Print `(sealed)` there.
5. MEDIUM-UNKNOWN (UNVERIFIED on Fly): `operator_health.clock_synced()` returns `adjtimex() != TIME_ERROR`; the rotator PREFLIGHT requires `clock_synced() is True` or it skips with `clock` (rotation.py `_preflight`). On the GX10 host it returns True (probe). On a Firecracker VM (Fly) or a container host without NTP/chrony the kernel can report TIME_ERROR indefinitely, in which case the Fly rotator would skip every run as "clock" with no rotation ever. Probe `operator_health.clock_synced()` inside a Fly machine before R7 is built; do not assume.
6. INFO: `key_grace_active` is hard-coded False and documented (K4 not merged). `expiry_min` ignores sealed and revoked rows by design.
7. Positive: witness values are re-validated before being ledgered (`_witness_fp`, `_witness_rows`: fingerprints 16-hex/(sealed)/null/(not shown), ids via printable_id, statuses enum, counts bounded to 10**12, generations to 2**53); append failures keep the last recorded state so the event is retried next tick (`_write` returns False before state is updated); `--add-to` validates the WHOLE document before writing and refuses format 2 (`doc.get("format") == FORMAT_2`).
