FINDING F-C213-1 MEDIUM (PROVEN, regression vs main 7b54f26): `socket.inet_aton` on glibc accepts trailing whitespace and text. `cleartext_ok("http://127.0.0.1 .evil.example.com/")` is True on the PR head and False on main; `urlparse` host is `127.0.0.1 .evil.example.com`, httpx host is `127.0.0.1%20.evil.example.com` (a DNS name, not an address). Same for `http://10.0.0.1 .evil.example.com/`, `http://127.1 .evil.example.com/`, `http://127.0.0.1 evil/`, `http://0x7f.1 attacker.example.net:8009/`. A hostile base URL of this form passes the allow-list and the key goes in clear to whatever `127.0.0.1%20.evil.example.com` resolves to. (Control characters \x0b and \x0c: allowed by cleartext_ok, httpx raises InvalidURL, so no connection.) Fix: refuse any host with whitespace or characters outside [0-9A-Fa-fxX.] before inet_aton, or accept only the strict dotted forms.
