## OBJECTIONS FIRST
1. F-C618-1 MEDIUM-LOW (the gap count is pinned too loosely, and its unit is a failed record, not a failed kill): `test_a_failed_ledger_write_is_counted_and_logged_without_its_message` asserts `ledger_note_failures >= 1`. The mutant that adds 2 per failure and the mutant that assigns 1 instead of incrementing both SURVIVE the whole kill-switch suite (198 tests); only "no count" and "adds 0" die. What the counter counts, probed with a ledger stub that always raises: one `/kill` produces two failed appends (counter 2), a following `/revive` one more (counter 3); so the number is failed RECORDS since process start, not failed actions, and it never resets (a ledger that recovers leaves it at its value: 803 after my test, unchanged by a later successful kill). The README says "the `ledger_note_failures` counter on `/health`" without saying either. Pin an exact count after one kill (2) and after two kills (4), and say in the README that it is per record and per process.
2. F-C618-2 LOW (control-character boundaries are not pinned): the rule refuses `ord(ch) < 32` and 127. The mutants `< 31` (lets 0x1f through), no 127 (lets DEL through) and `<= 32` (also refuses a plain space) all SURVIVE; the tests use `%00` and `%0a` only. Pin `%1F`, `%7F` and `%20` (a space in a path stays accepted, as today).
3. LOW (stated limits and the decision, none a defect):
   - Over-refusal is the declared decision (F-C525-2): a path holding a self shape is refused on ANY host, so an agent whose own endpoint is `/v1/kill`, `/api/health` or contains a `/heartbeat/` segment gets `skipped: self_endpoint` and no halt signal (visible in the report). In my set 70 of the spellings are refused that the router would not serve; that is the price, pinned by `test_the_guard_is_by_path_alone...`.
   - The counter is an unsynchronised `+= 1` on `app.state` from request threads. 400 concurrent kills (8 threads against a stub ledger that counts each call under a lock) gave 803 calls and a counter of 803, 0 lost updates under CPython 3.12's lock; I do not claim it for a free-threaded build.
   - `_canonical_path` refuses a `%` that survives one decode, so a literal `%` that is not an escape (`/a%zz`) is also refused as self: nothing legitimate needs it, and the README says so.
4. NOT A DEFECT, checked because the card said "path-decoding bypasses": the guard is applied to `urlsplit(endpoint).path`, and the request is sent for the whole `endpoint`; I compared the two parsers for the HOST as well (29 spellings: backslash and `@` games, `#`, `?`, tab and newline, a space, trailing dot, upper case, fullwidth and ideographic-full-stop forms). No spelling gives a host the allowlist accepts while httpx connects elsewhere; the only difference is a space after the host (`allowed.example /x`: urlsplit reads `allowed.example`, httpx connects to `allowed.example%20`, a name that does not resolve). Tab and newline are removed by `urlsplit` but rejected by httpx (no request is made).
5. EQUIVALENT survivors: dropping `"/kill/domain/" in path` and dropping `endswith(f"/kill/{agent_id}")` (both are covered by the `/kill/` shape in the list below); the log label wording.
