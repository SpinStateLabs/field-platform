# C-156 reviewer report: services/claude-approver decision, signing and secret handling (main 70fa59f)

VERDICT: the allow path is fail-closed and produced in one place. Two design limits matter more than any survivor: an ALLOW authorizes a tool NAME (the sentinel is never shown the tool's input and `irreversible` is hard-coded false), and `POST /halt` is reachable on a header marker only. 221 mutants run, 164 killed, 57 survived.

1. I read `_check`, `_answer`, `halt`, `api.py` in full and the rest through survivors; `config.py` and `core.py` poller code only by mutation.

3. 221 mutants from two generators is not a coverage figure.

2. MEDIUM, F-C156-1 (design): what an ALLOW authorizes. The sentinel request body is `{agent_id, action, token_id, irreversible: False, context}` (core.py:379-386) with `context` = {source, console_session_id, console_agent_id, tool_name, event_id, event_type, mcp_server_name, session_thread_id} (:640-652). The tool's INPUT is not sent, `action` is the mapped action name (`config.resolve_action`), and `irreversible` is the constant False, so no irreversible-action rule can fire on an approver-driven call; the sentinel decides on the tool NAME and the agent's scopes. A passing check proves "this agent may use a tool of that name", not "this call is safe". The README should say so under Declared. [HIGH on the code; MEDIUM that no sentinel rule depends on tool input: not read]
