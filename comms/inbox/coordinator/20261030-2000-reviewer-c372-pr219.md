## OBJECTIONS FIRST
1. The injection rule has spellings it does not see. Probes through the lint (the real `lint()` on synthetic workflows), each placed in a `run:` line:
   - `${{ toJSON(github.event) }}` is NOT flagged (the pattern needs a `.` or `[` after `event`); pasting the whole event into a shell line is a common debug idiom and carries every attacker-controlled string.
   - `${{ inputs.name }}` and `${{ inputs['name'] }}` (workflow_dispatch and workflow_call inputs) are NOT flagged, while `${{ github.event.inputs.name }}` is. The card asked for the workflow_dispatch inputs "if the builder claims them"; the PR does not claim them, but they are a standard injection source and are not listed as uncovered.
   - upper or mixed case (`${{ GITHUB.HEAD_REF }}`, `${{ GitHub.Event.Pull_Request.Title }}`) is NOT flagged: the pattern is case-sensitive. GitHub's expression syntax treats context and property names case-insensitively (general knowledge, MEDIUM); a one-flag fix.
   - bracket access on `github` itself (`${{ github['head_ref'] }}`, `${{ github["event"]["pull_request"]["title"] }}`) is NOT flagged (the pattern requires `github.`).
   - an expression with `}}` inside a string literal (`${{ format('}}', github.head_ref) }}`) ends the match early and hides the rest (an edge case).
   F-C372-1 MEDIUM-LOW (PROVEN).
2. The "safe patterns stay green" requirement of the card is only partly pinned. The file tests the `env:` passthrough and `github.event_name` / `secrets` / `github.sha`; it has no test that the same event expressions in `with:`, `if:` or a step `name:` stay green, so a lint that started scanning `with:` values (a mutant of mine) survives. F-C372-2 LOW.
3. Composite actions are not scanned: the discovery patterns are `.github/workflows/*.yml` and `*.yaml`, and a composite action's steps live under `runs.steps` in an `action.yml` elsewhere. None exists on main (`.github/actions` is absent), so nothing is missed today. F-C372-3 LOW (document or extend when one appears).
4. A job-level or top-level `permissions: write-all` passes the permissions rule (presence only), and `workflow_run` and `issue_comment` triggers are not flagged. The PR says the latter are not covered; the former is by design. LOW, no action.
