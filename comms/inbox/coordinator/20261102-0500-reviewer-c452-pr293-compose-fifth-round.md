## OBJECTIONS FIRST
1. F-C452-1 MEDIUM (decision (b) is not applied to its own stated rule: operator and spelling forms of an unresolved head): "an unresolved variable followed by a credential tail is refused" holds only for the exact forms `${A}/...` and `$A/...`. Probed through `_binds_forbidden_host_path`, all GREEN: `${A:?}/.ssh`, `${A:?e}/.config`, `${A:+x}/.ssh`, `${A:=/x}/.kube` (the `${DATA_DIR:?set it}` form is the ordinary compose way to require a variable), and, because the tail is matched un-normalised (`_normal_root` returns a non-absolute path unchanged): `${A}/./.ssh`, `${A}//.ssh`, `$A/./.aws`, `${A}/a/../.aws`, and the trailing-slash parents `${A}/.config/`, `${A}/.local/share/`. Contrast the pinned `/home/spinner/.config/` and `/home/spinner/./.config`, which are red. `${A}/.ssh/` is red only because that regex ends with `(/|$)`. Fix: match the head with any `${NAME<operator>...}` and run the tail through the same dot and slash normalisation as an absolute path.
2. F-C452-2 MEDIUM-LOW (decision (a), PWD as the repository root, is wrong as a model): PWD is the shell's working directory, not the compose project directory, and compose does not use it for relative paths. Run from a home directory, `${PWD}/.ssh` is `~/.ssh`. The checker reads PWD as `../..` and so `${PWD}/.ssh`, `${PWD}/.aws`, `${PWD}/.gnupg`, `${PWD}/.config`, `${PWD}/.kube`, `${PWD}/.netrc`, `${PWD}/.docker`, `${PWD}/.local/share` are GREEN (probed), while `${PWD}/..` is red. Nothing in the repository uses `${PWD}` in a compose file (git grep: one shell `$PWD` in ci.yml, not a compose source). The stricter and simpler rule is to refuse any bind source that begins with `${PWD}`, `$PWD`, `${OLDPWD}` or `$OLDPWD`; the climbing and `.git` pins stay true under it. As the PR has it, "stricter of runbook root and CI integration/demo" is only stricter for those two values.
3. F-C452-3 LOW-MEDIUM (credential variables are checked at the head of the raw source only): `${A:-${GNUPGHOME}}`, `${A:-$KUBECONFIG}`, `${A:+$GNUPGHOME}/x`, `${A}${GNUPGHOME}`, `${A}/${GNUPGHOME}` and `/${GNUPGHOME}` are GREEN; the check runs on `source.strip()` before `_expand_defaults`. Run it on the expanded text too, and refuse a credential variable anywhere in the source. The variable list itself is eleven names; not on it, GREEN: `AWS_CONFIG_FILE`, `KUBE_CONFIG_PATH`, `DOCKER_CERT_PATH`, `NETRC`, `CLOUDSDK_CONFIG`, `AZURE_CONFIG_DIR`, `GH_CONFIG_DIR`, `TF_CLI_CONFIG_FILE`, `PGPASSFILE`, `HELM_CONFIG_HOME`, `REGISTRY_AUTH_FILE`, `NPM_CONFIG_USERCONFIG`, `GIT_CONFIG_GLOBAL`, `SSL_CERT_FILE`, `ANSIBLE_HOME`, `RCLONE_CONFIG`.

## DESIGN DECISIONS JUDGED

(b) An unresolved variable with no known meaning stays legal unless a credential tail follows: a defensible policy (the estate's `.env` decides; an unknown name cannot be resolved by a static test), but its stated exception is incomplete (F-C452-1) and it is the reason `${A}/etc` and `${A}` are green. If Don wants the class closed, the structural answer is an allowlist: a bind source must be a named volume, a path inside the repository by relative or `${PWD}`-free form, or one of the few host paths the compose files actually use (their count is small; the existing real-file test already shows the base and GB10 files pass).
