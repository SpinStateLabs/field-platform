## Blocking finding (B1, HIGH, reproduced)
`_set_active` in services/federation-broker/src/federation_broker/cli.py calls module-level `httpx.get(...)` and `httpx.put(...)` with no `trust_env=False`. httpx reads HTTP(S)_PROXY / ALL_PROXY for those calls (general knowledge), so the `x-field-auth` secret, the operator pair from `_hdr("PUT", ...)` and the contract's pasted public key travel through an ambient proxy. This is the same class PR 939 (S10-12) fixes in spend-governor and the class the C-57 lint exists to stop.
The repo lint catches it: `tools/tests/test_http_env_proxy_lint_c57.py::test_the_repo_matches_the_allowlist` FAILS on this head with `new unproxied-env client ... federation_broker/cli.py::_set_active::httpx.get x1` and `::httpx.put x1`. The same test file passes on current main (102 passed, main 45bd655) and the PR does not touch tools/tests/http_env_proxy_allowlist.txt, so the failure is attributable to this PR. Adding allowlist entries is NOT an acceptable fix: it would legitimise sending the operator pair through the proxy.
Required fix: send both calls through one `httpx.Client(trust_env=False, follow_redirects=False, timeout=10.0)` (as PR 939 does for spend-governor, or as the kill-switch/lifecycle CLIs already do), keep the allowlist unchanged, re-run the lint.
