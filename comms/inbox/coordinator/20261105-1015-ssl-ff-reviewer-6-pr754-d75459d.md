## Objections first (FORCE-O)
1. The motive is a signed-document one: `sources` is caller-supplied on POST /crosswalk and /pack, so before this change a body with `ledger_verify: {"ok": "false"}` was a verified chain (truthy string) and a token row with `revoked: "false"` was a revoked token. The same reading error I found in PR 692 (attestation-reporter) and PR 736 (lifecycle decommission), here on the third service. The common cause is that three services each re-implement "read a flag"; there is no shared helper (field-core has none that I know of), so each fix is local and the next reader can regress it. MEDIUM as a pattern; each fix is correct.
2. Only three controls were hardened: FC-L-01 (`ok`), FC-D-02 (`revoked`) and FC-I-01 (`owner`). The other evidence reads use presence or counts (`registry_record is not None`, `governor_cap is not None`, `len(tokens)`, event counts), which are not flag reads, so I did not find another truthiness site in `_evidenced` (read the function on main, not every caller). I also checked the input model: `EvidenceSources` already rejects a non-dict `tokens` item, a string `ledger_verify` or `registry_record` at validation (measured: `ValidationError` for each), so those cannot reach `.get`.
3. FC-L-01 with a missing key or an empty dict reports `ledger verify failed: None` (pinned as is); the reason text comes from the caller's own `reason` value, so a long or odd `reason` is printed in the pack's evidence detail (that detail is made one line and capped in PR 693, which I reviewed; this PR does not depend on it).
4. A JSON `true` is required, so a legitimate upstream that serialises booleans as the strings "true"/"false" (not what the ledger's `/verify` does, as far as I know) would now read as unverified; the stricter reading is the safe side for an evidence pack.
Steelman: a signed evidence pack must not say "ledger chain verified" or "token revoked" on the strength of a string; now only a JSON `true` counts, a blank or non-string owner is "no owner", and each wrong-typed value in the tests (the strings "false", "no", "yes", "true", numbers 0, 1, 2 and 1.0, null, empty list and dict, empty string) is refused, with the legitimate cases (a real owner with commas, a padded owner, "0" as a name) still passing.
