## OBJECTIONS FIRST (the predicate, all measured; HIGH)
1. Names are trusted by SHAPE, never resolved. With `allow_names=True` (the default, used by `llm.py` for `FORCE_GATEWAY_URL` and `ANTHROPIC_BASE_URL`) any single-label name, `*.internal` and `*.local` host counts as estate-internal, whatever it resolves to. A single-label name that a resolver completes with a search domain, or an `evil.internal` served by a resolver the estate does not control, would receive the key in clear. The card asks about "DNS names resolving internal": the predicate does not resolve anything, by design (a compose service name is not known statically). The three tool copies and the field-agent copy use `allow_names=False` (addresses and `localhost` only), which is the safe setting for tools that run on operator machines. F-C689-1 LOW to MEDIUM (document the trust in the docstring and in the runbook; consider `allow_names=False` plus an explicit allow-list for the one compose service name).
2. Numeric-looking single labels that `inet_aton` rejects are accepted as service names: `4294967296`, `0x`, `08`, `deadbeef` all answer True with names allowed (they match the numeric charset, `inet_aton` raises, the name rule then sees a single label). No resolver treats them as addresses, so the realistic risk is a DNS lookup of a nonsense name; same behaviour as the old copies, so not a regression. F-C689-2 LOW (require at least one letter outside `[0-9a-fx.]` for a name, or refuse an all-numeric label).
3. The "no second policy" lint is blind to the other `ipaddress` predicates: with a scratch file containing `.is_private` the lint goes red, with a file containing only `.is_link_local` it stays green. Today nothing outside field-core uses `is_link_local`, `is_global`, `is_reserved` or `is_loopback` (git grep: 0 sites), so the policy is single; but the lint does not keep it single. F-C689-3 LOW (scan for every `is_*` attribute of an address, or for `ipaddress` imports outside field-core).
