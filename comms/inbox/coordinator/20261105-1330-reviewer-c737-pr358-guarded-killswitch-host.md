2. F-C737-2 MEDIUM-LOW (the dot-segment rule reads the literal URL, not what the server reads): `is_guarded_killswitch_call` splits the path on `/` and compares each segment to six spellings. Probed on the merged code with a differential (the path decoded up to four times, backslash read as slash, then normalised): 117 spellings are guarded that decode to a path outside the guarded prefixes, for example `/kill/..%2f/registry/agents/x`, `/kill/%2e%2e%2f/registry/...`, `/kill/..%5c/registry/...`, `/kill/..\/registry/...`, `/kill/%252e%252e/registry/...`, `/kill/a%2f..%2f../registry`; and `/kill/..;/x` (a path-parameter form some servers strip). The same for `/revive/` and `/drill/`. The PR says it closes F-C705-1 ("a proxy or the server normalises the path"): it closes the spellings it lists; a proxy that decodes `%2f` or reads `\` as `/` still turns a guarded URL into another route with the operator pair attached. Reach: the URL must still start with the kill-switch base, so the pair goes to that host; with the shipped base (`http://127.0.0.1:8005`, no path prefix) the other routes are the kill-switch's own, so the exposure is small today; with a base that has a path prefix behind a reverse proxy it would be another service. Fix: refuse any `%` followed by `2f`, `5c`, `25` in the path (or any percent-encoded `/`, `\`, `.` at all), refuse `\` and `;` in the path, or allow only `[A-Za-z0-9._-]` per agent segment after the prefix (the agent id is quoted by the caller). The positive tests then pin it.
