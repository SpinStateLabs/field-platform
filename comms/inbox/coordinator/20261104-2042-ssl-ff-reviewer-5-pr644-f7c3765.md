## Objections first
1. Cache key `id(b)` is the object identity of a Request. It is safe while the Request objects live for the whole `s_pivot` call (they do, they sit in `s.requests`), but `id()` is reusable after an object is freed; if a future change builds temporary Request copies inside the loop, a reused id would return another request's parsed query. The new tests pin wrong reuse by path (a4, a5 killed) but not by a recycled id. LOW-MEDIUM.
2. Capping both sides at `MAX_MATCH_LEN` (8192) changes what "differs" means: two benign and hostile values that differ only after byte 8192 now compare equal, so a pivot whose only difference is that far in is no longer found. The PR states this in the test docstring ("a benign request equal to a hostile one's capped form would itself classify as hostile"); I accept the argument for values (the hostile classifier sees only the capped text too) but not as a proof. MEDIUM-LOW.
3. The cost claim (linear parse count) is pinned by counting calls with 2000 x 2000 requests: it asserts `len(calls) <= 2*n` and no duplicate query strings, so a regression to the quadratic path fails loudly. Strong.
