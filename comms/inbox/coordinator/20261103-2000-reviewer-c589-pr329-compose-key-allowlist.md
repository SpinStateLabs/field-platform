The same class is already accepted on purpose in the real default `${FIELD_CALLER_KEYS_DIR:-<root>}/registry` (K replaces the whole directory), so this is not closable statically; the honest statement is "C-506 closes four spellings, not the class". Fix: either refuse any literal remainder that continues a path after an expansion whose default is a proper prefix of an allowed root, or state the limit in the rule comment and make the PR 328 resolved gate the named closer.
- F-C589-2 LOW-MEDIUM (PROVEN): `build.dockerfile` is checked as a path relative to the COMPOSE directory (`_relative_source_escapes` depth 2), but compose resolves it from the build CONTEXT. With `context: ../..` and `dockerfile: ../../secret` the whole check ACCEPTS a Dockerfile two levels above the repository root. Opposite direction also wrong (over-refuses with a shallow context). Fix: resolve the dockerfile against the context before the escape test, or allow only a name with no `..`.

Fix: allowlist the keys of top-level volume, secret and config entries (`driver`, `driver_opts` with `type`, `o`, `device` only, `external`, `name`, `file`) as for services.
