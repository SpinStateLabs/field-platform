## Objections first (FORCE-O)
1. A model-level refusal is a behaviour change for every reader of a stored token: services/delegation-authority/src/delegation_authority/store.py:70-81 builds the token from stored text with datetime.fromisoformat and does not catch a ValidationError. A legacy row holding a naive time would now fail to load (see F1). I do not know whether any such row exists in a real database (not in source).
2. api.py:117-120 still says "A naive stored value is read as UTC": that helper now has a dead branch for tokens (F2, documentation only).
3. The author first coerced naive to UTC and CI showed that defeated tools/generate_doa_roster.py's own refusal (the test file docstring says so). The final choice, refuse at the model, is the stricter one and matches that tool's policy. Steelman for coercion: it would not break a legacy naive row. Rejected: assuming UTC for delegation-of-authority data is a silent authority-window shift of up to the offset, which is worse than a loud refusal.
