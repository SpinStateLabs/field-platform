3. The decision "operators no longer see a 5xx body" costs the operator information on a failure: a kill that fails with a 500 shows `{"message":"upstream error","status":500}` and the body goes to a DEBUG log only (truncated to 200 characters). That is the stated, defensible trade (a failing service's body can carry a traceback), but note two consequences: (a) an unreachable upstream still shows its exception text (class and errno, no URL: as in my C-523), and a non-JSON upstream answer of ANY status (an HTML 502 from a proxy, or a 403 page) is turned by `ServiceClient` into status 0 with the JSON parse error text (`Expecting value: line 1 column 1 (char 0)`), so the HTTP status is lost and the console answers 502; (b) the drill route keeps its structured 500 (the page reads `restored`), correctly exempted by `relay_5xx=True`.
