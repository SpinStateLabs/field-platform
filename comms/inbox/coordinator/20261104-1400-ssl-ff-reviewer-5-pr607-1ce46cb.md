## Objections first
1. Behaviour change under load: a registry outage now returns 200 with a degraded report, a ledger or delegation outage returns 502. A caller that only reads the status code will treat a degraded report (no owner, RACI "Responsible" = `<registry unreachable>`) as complete. The degradation is stated in `integrity_notes` and the markdown, which is right, but it is the caller's job to read it. MEDIUM.
2. The `ValueError` arm of every upstream `except` (verify, events, delegation) is unpinned: a 200 with a body that is not JSON is the case. Without it the failure is a 500 with a traceback-class response, which is exactly what S2-23 set out to remove. The tests only use transport errors and 4xx/5xx statuses.
3. A delegation body that is not a list is a designed branch (the `isinstance` checks and the "1 ... unreadable" note) with no test that sends one.
4. A single `UpstreamUnavailable` hides which call failed beyond the name: fine for security, harder for an operator. LOW, design choice.
