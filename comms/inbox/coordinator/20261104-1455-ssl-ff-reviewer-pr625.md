## Objections first (FORCE-O)
1. The refusal line prints the manifest path the caller gave and the exception CLASS name, not its text (the comment says a YAML error quotes the file's content), which is the right choice; but the `templates --out` write failure and the unknown-template message are different shapes (`cannot write {out}: <ClassName>`, `unknown template 'x'; choose from ...`); the test for the first does not pin that the text is never echoed (T7 survived).
2. `except (OSError, UnicodeDecodeError, yaml.YAMLError, ValueError)`: UnicodeDecodeError is a ValueError subclass, so naming it is redundant (V3, equivalent). A broad ValueError also catches ValueErrors that do not come from reading the file (for example a bug inside validation) and reports them as "cannot read manifest"; mislabelling risk, LOW.
3. `import yaml` is added to field-core's cli; field-core already imports yaml in validation.py (I saw `import yaml` at validation.py:23 earlier in this session), so no new dependency.
Steelman: the PR does what validation.py's own docstring promises ("a gap report, not a stack trace"): directory, invalid YAML, a YAML list, invalid UTF-8 and a missing file each end in a one-line exit 2 with no traceback, in both text and `--json` mode, and an unknown template names the four valid ones.
