## Residual outside this PR's stated scope (not a condition)
Inbound `/crossing` request fields are not bounded and are echoed into the verdict and the hash-chained ledger row. With 200,000-character values on the head:
| Field | Verdict size | Ledger row |
|---|---|---|
| counterparty_org | 600,345 bytes | 400,195 bytes (largest row) |
| counterparty_agent_id | 200,467 bytes | about 200,000 |
| scope | 200,466 bytes | about 200,000 |
| data_class | 200,473 bytes | about 200,000 |
These come from the caller's request, not from the manifest, and the PR and its docstring speak only of manifest gap text, so I do not treat this as a defect of the PR; the docstring's wording "a multi-megabyte audit row on every refused crossing" applies equally to these fields, so a follow-up card is warranted (the same cap on the request model, or the same helper on the reasons). I did not measure outbound request fields or the authentication needed to reach the route (MEDIUM).
