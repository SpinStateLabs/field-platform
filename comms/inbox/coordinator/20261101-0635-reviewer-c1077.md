### force-gateway
F-C1077-FG-1 MEDIUM-LOW (PROVEN, class: value echo into a startup error). Five bare environment parses in `create_app` still echo the bad value in the `ValueError`: `FORCE_HYGIENE_WINDOW` (api.py:795), `FORCE_HYGIENE_BAND` (:796), `FORCE_HYGIENE_BASELINE_WINDOWS` (:797), `FORCE_GATEWAY_LATENCY_BUDGET_MS` (:801), `FORCE_GATEWAY_BYPASS_COOLDOWN` (:804). Probe: a canary string in each variable; 5 of 5 exception texts contain it. This is the class C-502, C-582 and C-734 closed at the posture flags, the numeric tunables and the sentinel URL; C-734 objection 3 predicted that the fix per call site leaves new sites. A secret pasted into the wrong variable lands in the startup traceback and the container log. Proposed card: one parametrised test, canary in each of the five variables, `create_app()` raises and the text lacks the canary and names the variable; plus C-734's AST lint over bare `int(`/`float(` on `os.environ`.

F-C1077-FG-2 MEDIUM-LOW (PROVEN, class: degenerate configuration disables an alarm or crashes the sampler). `float()` accepts `nan`: with `FORCE_HYGIENE_BAND=nan`, `drift.py:91` (`abs(mean - baseline) > band`) is never true, so the drift alert never fires. Probe: 10 stable scores then 20 collapsed ones: default band alerts once, `nan` band never. `FORCE_HYGIENE_BASELINE_WINDOWS=0` raises `ZeroDivisionError` at drift.py:88 on the first completed window (an empty slice), so each instrumented sample then faults and the gateway drops to bypass (`instrumentation_fault`): a coverage gap, never an outage, but silent to a caller. A negative band alerts constantly (loud, so only INFO). Proposed card: validate at startup (finite band >= 0, window >= 1, baseline windows >= 1) with a value-free message; tests: `create_app` with `nan`, `-1`, `0` for each raises naming only the variable.

F-C1077-FG-3 LOW (PROVEN, class: untested branch with a real behaviour). ### sealed-ledger
F-C1077-SL-1 MEDIUM-LOW (PROVEN, class: replay inside a window). A caller claim is accepted any number of times while its `caller_ts` is inside the window (`CALLER_TS_MAX_AGE_S = 300.0`, store.py:138; `_verify_claim`, store.py:436; the signed bytes are event_type, agent_id, payload, caller_id, caller_ts only, signing.py `caller_signing_bytes`). No nonce, no seen set. Probe: one signed claim, three appends: 3 of 3 accepted, 3 events stored. Effect: a captured POST body re-posted N times writes N identical audit events (inflates counts: spend, start-type events). Precondition: the body and the perimeter secret (when authn is on). C-40 listed this as not examined; R-09 found the same class in federation-broker. Proposed card: a bounded seen set of (caller_id, caller_signature) kept for window plus skew; test: the second identical POST inside the window is 403 and the ledger length is unchanged.

F-C1077-SL-2 MEDIUM-LOW (PROVEN, class: server-side path from the caller). `POST /export` writes the bundle to any absolute directory the process can write unless the operator mode is armed: `target = Path(out_dir)` (api.py:457), confinement only under `if operator_auth.mode() != operator_auth.OFF` (api.py:458). Probe, default flags: `out_dir=<tmp>/nested/anywhere` -> 200, the timestamped bundle directory created there. The bundle is ledger content. The same route echoes the OS error with the full server path in a 500 (api.py:486 `detail=str(exc)`; probe: `[Errno 20] Not a directory: '<path>'`); the same `str(exc)` 500 echo is at api.py:410, :505, :529, :545, :573 (LedgerCorrupt and OSError texts name files). Proposed card: confine `out_dir` to the export root in every mode (default root `<ledger dir>/exports`) and answer 500s with a fixed text plus a log line; tests: `POST /export?out_dir=/tmp/x` with flags unset -> 422; an OSError during export -> the body contains no path. Note: tests may pin the current behaviour (the API tests export to a temp path); a confinement change needs those tests moved under `FIELD_EXPORT_ROOT`.

F-C1077-SL-3 LOW (PROVEN, class: no size bound). `POST /events` has no body cap: an 8 MiB payload -> 201 and 8,388,913 bytes appended (probe). `GET /events` returns up to 10,000 events with no byte cap, and every event when `limit` is omitted. No sealed-ledger test names a size limit (grep for 413, max_bytes, too large: none). Proposed card: a validator on the serialized size of `payload` (a documented limit, 422) and a byte cap on the list response; test: an oversize append is refused and the ledger length is unchanged.

F-C1077-SL-4 LOW (READ): `POST /retention/apply` takes `allow_external` and `archive_dir` from the request body (api.py:561, :563; model at api.py `RetentionApplyRequest`), so any caller past `guard_retention` (flags unset: any perimeter-secret holder) can send closed ledger segments to any same-filesystem directory outside FIELD_DATA_DIR. The CLI's `--allow-external` is an operator typing a flag; the API's is a body field. Moves are renames, never deletes (store.py docstring) and the retention event records them. Proposed card: gate `allow_external` on an environment switch for the served route; test: `allow_external=true` without it -> 422.

F-C1077-SL-5 INFO (READ): the docstrings of `rotate`, `place_hold`, `release_hold` and `retention_apply` sit after the first statement (api.py:491, :518, :534, :551), so they are string statements, not docstrings; the OpenAPI description of those four routes is empty. Test: `app.openapi()["paths"]["/rotate"]["post"]` has a description.
