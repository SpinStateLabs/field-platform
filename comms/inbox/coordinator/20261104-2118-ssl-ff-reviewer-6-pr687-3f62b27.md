## Objections first (FORCE-O)
1. Fail-closed is the point of this change, so the failure modes matter more than the happy path. I checked the three that would be unsafe: (a) a bad row read as ALLOW (E8, E9: the degraded entry allowing `*` is KILLED); (b) a bad row read as keyless (the `holds no counterparty key` reason is asserted absent, and E7 giving the entry a key is KILLED); (c) a bad winner falling through to a readable second row (E13 KILLED, by `test_an_unreadable_winner_does_not_fall_through_to_a_readable_second_row`). All three are pinned. HIGH.
2. The test "an inactive unreadable row does not block the org's active contract" is order-dependent and weaker than it reads: the inactive row `FED-OLD` sorts AFTER the active `FED-NEW` ("N" < "O"), so a mutant that reads inactive rows too (E14, `WHERE active=1` removed) still resolves to the readable `FED-NEW` and the PR's file passes. It is killed by a different test in the whole federation-broker suite (1 failed, measured). I confirmed the PR's test would catch E14 if the ids were flipped (an inactive `FED-A-OLD` before an active `FED-B-NEW`: 1 failed). LOW (rename the ids).
3. The `TypeError` clause is not exercised (E3 survives file and suite, 219 passed). The schema declares `allowed_scopes` and `allowed_data_classes` NOT NULL TEXT, so `json.loads(None)` is not reachable from SQLite; I did not find a stored value that raises TypeError (likely dead defence, LOW; not proven unreachable).
4. `list()` shows an unreadable row as INACTIVE with placeholder scopes `UNREADABLE`; a consumer that treats any non-empty scope list as "has scopes" would show it as a contract with scope "UNREADABLE". The `active` False and the contract_ref text mitigate (LOW, design).
Steelman: one corrupted row previously turned `GET /contracts` and every crossing for that org (and, for a list, every org) into a 500; now the listing is 200 with the bad id visible, the crossing is a ledgered BLOCK F.peer naming the id (the federation.block event count is asserted), other orgs are untouched, and a deeply nested scopes value (100000 brackets) is also refused cleanly (E2 KILLED).
