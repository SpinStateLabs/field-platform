## OBJECTIONS FIRST
1. F-C731-1 MEDIUM-LOW (the shared guard has no origin check): `field_core.guarded_operator.GuardedOperatorAuth.auth_flow` attaches the pair when `is_guarded(method, request.url.path, base, routes)` is true: the path alone. Probed with an `httpx.Client(auth=GuardedOperatorAuth("http://killswitch:8005", pair, KILLSWITCH_GUARDED))`: `POST http://evil.invalid/kill/a1`, `POST http://killswitch:9999/kill/a1`, `POST https://killswitch:8005/kill/a1` and `POST http://killswitch:8005@evil.invalid/kill/a1` ALL get the pair. The lifecycle `PerRequestAuthClient` in the same PR does check the origin (C-586 F-C586-3: another origin gets no credential, probed: no secret, no pair). The kill-switch CLI builds its client with a `base_url` and fixed relative paths, so nothing reaches another origin today, and `follow_redirects` is off; but the class is now described as "the one mechanism" and is exported. Fix: compare scheme, host and port with the base in `auth_flow` (as `_origin_and_path` does) and pin it with the four spellings above.
2. F-C731-2 LOW-MEDIUM (the F-C624-1 class remains in field-core): the lifecycle client was fixed to decide on the wire path; the field-core `RegistryClient` and `LedgerClient` still decide on the string the code builds before httpx normalises it (`_request_auth(own_client, "PATCH", f"/agents/{agent_id}", REGISTRY_GUARDED)`). Probed with a stub transport: `agent_id` of `..` attaches the pair to a PATCH whose wire path is `/` (the base), `.` to a PATCH of `/agents` (not a guarded route), `a/../tokens` (wire `/agents/tokens`) and `a1/attest` attach nothing. The over-grant stays on the same origin and the ids come from internal flows; the under-grant is a refused write. Not reachable from outside; deciding on the wire path there too (as in the lifecycle client) removes the class.
3. F-C731-3 MEDIUM-LOW (a boundary that the tests do not pin, and the builder's note is wrong about it): the builder says two base-prefix-boundary survivors are equivalent. One is (`startswith(prefix)` without the slash: the remainder cannot match a route that begins with `/`). The other is not: in `_origin_and_path` the mutant that drops the `startswith(prefix + "/") else None` test and slices anyway (`u.path[len(prefix):]`) SURVIVES the 248-test lifecycle suite, and in field-core `is_guarded` the mutant that drops the "path must start with the prefix" check SURVIVES the 1133-test field-core suite and the 164-test kill-switch suite. Reason: a foreign path of the SAME LENGTH as the base prefix slices to a guarded route. Base `/ks`, path `/ab/kill/a1`: sliced `[3:]` gives `/kill/a1`, which is guarded, so the pair would ride a request outside the base path. The real code refuses it (probed); no test has a foreign prefix of the same length (`/other/...` is 6 characters, `/ksx/...` is not a slice-match). Add `/ab/kill/a1` under `/ks` for both the client and `is_guarded`. Also unpinned in `GuardedOperatorAuth`: the decision on the DECODED path (`request.url.path`) against the raw path: a percent-encoded path (`/%6Bill/a1`) or a query (`/kill/a1?x=1`) would be missed by a `raw_path` mutant (survives); the real code uses the decoded path and gets both right (probed).
4. LOW (readings I checked and accept): `//kill/a1` is a network-path reference that httpx turns into a path under the base (`/a1`, no credential beyond the secret); a trailing slash (`/kill/a1/`) is not guarded (the receiver would redirect it; redirects are off); a path outside the base path on the same origin gets the secret only; a percent-encoded slash before the id (`/kill%2Fa1`) is decided as `/kill/a1` (what the receiver's router sees) and gets the pair. A tab in a path is refused by httpx before sending.
5. EQUIVALENT survivors: the `is_absolute_url` shortcut (httpx adds the slash itself, the builder simplified it), the `params` argument and the method of the throwaway wire build (they do not change the URL), `startswith(prefix)` without the slash.
