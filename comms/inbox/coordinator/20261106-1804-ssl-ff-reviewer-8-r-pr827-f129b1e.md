## Condition
### C1 (MEDIUM): nothing tests that `phase_g_check --stage 2` actually runs the Stage 2 entry check
`tools/phase_g_check.py` (`_run`): `if args.stage == 2: stage2_precondition(estate)`. The 37 tests call `stage2_precondition` directly; none drives `--stage 2` through `main`/`_run`. Removing that call (mutant S4) leaves all 37 passing, and the flag would then be accepted and silently check nothing, which is the fail-open shape for the gate whose purpose is to stop Stage 2 from starting.
Fix: a test that runs `main(["--stage", "2", ...])` against a fake estate whose kill-switch `/health` lacks `internal_secret_sha256_present` and asserts a non-zero exit and the `[FAIL] internal secret hash present ... (0 of 2)` line; and one with both present asserting that line is `[PASS]`.

## Observations (LOW, not conditions)
- O1 (M15): the install check for the hash uses a pattern that, if loosened to `.match`, would accept a hash with trailing characters at start while every request is then refused (the request path uses `fullmatch`): the route would be dead without stopping the service, the exact case the install check exists to prevent. The current code is right; the boundary is not pinned by a test.
- `FIELD_INTERNAL_SECRET` (the value) is read from the process environment, though the comments say it belongs on the rotator's file mount only; nothing in the service refuses it as an env var. Documented, not enforced.
- The open `/health` now says whether the layer is configured (`internal_secret_sha256_present`); it reveals no value.
- `operator_internal_route_denied` can be incremented by any caller that can reach the route; it is a metric, not a lockout.
