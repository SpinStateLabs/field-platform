## OBJECTIONS FIRST (all PROVEN on the GX10 against the audit script, `node innerhtml_audit.mjs <acorn> <page>`)
1. F-C508-1 MEDIUM-LOW: the script filter skips executable scripts. In `innerhtml_audit.mjs` the regex `!/\btype\s*=\s*["']?(?!module|text\/javascript)/i` lets the optional quote match nothing, so for a QUOTED type the lookahead sees the quote character and the script is excluded: `<script type="module">`, `<script type="text/javascript">`, `<script type="application/javascript">` and `<script type="text/jsx">` give `scripts=0` and an unsafe `x.innerHTML = a.name` inside is NOT reported; the same scripts with an unquoted type, no type, `defer`, `nonce` or `language` attributes are audited. Today the shipped page has `<script type="application/json">` (a data block, correctly skipped) and two plain `<script>` blocks, and the test asserts `scripts == 2`, so the page is covered; a future `type="module"` script would not be. Fix: parse the attribute value properly (capture the value, then allow empty, `module`, `text/javascript`, `application/javascript`).
2. F-C508-2 MEDIUM-LOW: any call named `esc` is trusted whatever it resolves to. `esc` is also looked up in a name-keyed map (last declaration wins). Probes: a second `var esc = s => s` AFTER the real one is caught (the `esc` self-check then fails); but a shadow BEFORE the real `esc`, a function parameter named `esc` (`function g(esc){ x.innerHTML = esc(a.name) }`), and a loop or catch variable named `esc` all pass clean. `function esc` and `var esc` redeclared after are caught. Fix: resolve `esc` by scope and require the binding to be the audited top-level one.
3. F-C508-3 MEDIUM-LOW (a class the audit blesses): `x.innerHTML = \`<button onclick="del('${esc(a.id)}')">x</button>\`` passes as safe. It is not: `esc` is an HTML escape, and an `onclick` attribute value is HTML-decoded before the JavaScript runs, so `&#39;` becomes `'` and breaks out of the JS string. The shipped page does NOT do this (0 templated `on...="${` handlers; it uses `data-id="${esc(...)}"` with `onclick="killAgent(this.dataset.id)"`, the safe pattern), but nothing keeps a future edit from doing it. Fix: reject a template expression inside an `on*=` attribute (and inside `javascript:` URLs), or require `this.dataset` there.
4. F-C508-4 LOW to MEDIUM (unrecognised sinks): the audit recognises `innerHTML`/`outerHTML` assignment, `insertAdjacentHTML` and `document.write`. It does not see (all `sinks=0` on a page that uses them with data): a computed `x["innerHTML"] = data`, `Object.assign(x, {innerHTML: data})`, a destructuring assignment to `x.innerHTML`, `document.writeln`, `iframe.srcdoc`, `Range.createContextualFragment`, `DOMParser().parseFromString`, `setAttribute("onclick", data)`, `a.href = data` (a `javascript:` URL), `eval`, `new Function`, `setTimeout(<string>)`. The shipped page uses none of them except `insertAdjacentHTML` (line 1043, audited) and `a.href = url` for a blob download (lines 1276 and 1804, not an HTML sink). Also the `.replace` pass-through rule trusts `esc(a).replace(/&lt;/g, "<")` and a helper that un-escapes `esc(...)` output (probes pass clean): a literal replacement can re-introduce markup.
5. The empty scan: the audit prints `sinks: []` for a page with no sinks and exits 0; the guard against a blind scan lives in the test (`scripts == 2`, at least 25 sinks, one clean `esc` check on the shipped page), which is the right place; the audit tool run alone cannot fail an empty scan.
