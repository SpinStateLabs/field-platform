# C-187 reviewer report: field-core llm.py and every LLM-calling component (main 2518d1d + PR 95 tests)

VERDICT: the shared helper's own logic is fully pinned (29 of 29 mutants killed) and sends the platform headers only toward FORCE_GATEWAY_URL; but on main there is NO shared https check (card C-117 is not built) and no caller builds a proxy-free client. Both gaps are proven below for the three platform callers.

OBJECTIONS FIRST
1. The card asks whether the https requirement "holds for each caller"; it cannot hold where it does not exist, so this report records the current absence and the shape C-117 must take.
2. I could not probe the claude-approver SDK client (the `anthropic` package is not installed in the review venv); that part is a read of its three lines.
3. No live LLM call was made; probes build the clients and read their configuration only.

ASSUMPTIONS
1. Main 2518d1d (+PR 95); `packages/field-core/src/field_core/llm.py` (110 lines; tests `test_llm.py`, `test_llm_f1.py`). Callers found by `grep` over packages, services, tools: force-gateway `hygiene_judge.py:114-123`, conformance-sentinel `judge.py:141-144`, compliance-crosswalk `suggestions.py:175-178` (all three via `field_core.llm`), claude-approver `client.py:23-25` (`anthropic.Anthropic(api_key=key)`), and force-gateway `api.py:202-215` `real_upstream` (deliberately does not use llm.py). [HIGH]

REASONING
1. How each caller builds its client: the three platform callers do `httpx.Client(base_url=anthropic_base_url(), timeout=30.0, headers=anthropic_headers(key))`; the approver builds the SDK client with only the API key (the SDK reads `ANTHROPIC_BASE_URL` itself: general knowledge, not probed here); the gateway's own upstream is covered by C-104/C-115 (warn once, opt-in `FORCE_GATEWAY_REQUIRE_TLS_UPSTREAM`). `grep trust_env` over those packages: 0 hits. [HIGH]
2. MEDIUM, F-C187-1 (PROVEN): no scheme check in the shared helper. Probe with `FORCE_GATEWAY_URL=http://gw.example.test:8009`, `ANTHROPIC_BASE_URL=http://plain.example.test:9000`, a shared secret and a self-identity pair set: `anthropic_base_url()` returns the plain-http gateway URL; `anthropic_headers("sk-ant-...")` returns `x-api-key`, `anthropic-version`, `x-force-passthrough`, `x-field-agent-id`, `x-field-token` and `x-field-auth` (the perimeter secret present). So a non-private `http://` gateway or base URL carries the Anthropic key, the shared secret and the token id in clear, with no warning and no refusal. Without `FORCE_GATEWAY_URL` the helper correctly sends only `x-api-key` and `anthropic-version` (the platform headers never go to ANTHROPIC_BASE_URL), and the base URL is still plain http. [HIGH]
3. MEDIUM, F-C187-2 (PROVEN): the three platform callers' clients honour environment proxies. Probe: with `HTTPS_PROXY` and `HTTP_PROXY` set, `httpx.Client(base_url=anthropic_base_url(), headers=anthropic_headers(key))` (exactly the callers' construction) holds 2 proxy mounts (`c._mounts`), so the Anthropic key and, toward a gateway, the perimeter secret and token id would be sent to the proxy. Same class as F-C41-1 (FieldClient, fixed in PR 68) and F-C55 (59 httpx sites). [HIGH]
4. LOW, F-C187-3 (read): the approver's `anthropic.Anthropic(api_key=key)` takes its base URL from the SDK's environment handling and passes no `http_client`, so neither a scheme check nor `trust_env=False` applies; the approver is not deployed today. [MEDIUM: read, not probed]
5. The shared function is well pinned: generator v1 2/2 and v2 27/27 killed over `llm.py` with `test_llm.py` + `test_llm_f1.py`: the precedence FORCE_GATEWAY_URL > ANTHROPIC_BASE_URL > default, blank-as-unset, trailing slash strip, both-or-neither identity pair, passthrough and `auth_headers()` only toward the gateway. [HIGH]
6. What C-117 should do (design, no code): put one `make_http_client(key)` (or `check_base_url`) in `llm.py` that (a) refuses an `http://` base URL whose host is not loopback or private when the call carries a key or any platform header (https, or private http, as `_base_url_warning` in force-gateway already decides), (b) builds `httpx.Client(trust_env=False, ...)`, (c) is the only way the three platform callers and the approver (via `http_client=`) construct a client; add a test that fails if a caller constructs its own client. Decide whether an unrecognised scheme refuses (recommended) or warns. [MEDIUM: design]

CONCLUSION
Two proven gaps (cleartext-capable base URL, env-proxy client) across the three platform callers; the shared helper is the right place for both fixes and is itself well tested. Not done: a live approver SDK probe; the gateway `real_upstream` (covered in C-115).
