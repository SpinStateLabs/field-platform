## Condition C1 (HIGH, measured on the head and on main): the claim is wider than the fix
The title and the test docstring say a damaged stored source record is "a named row, not a traceback". That holds for `run_check` and `check_file`. The status view `regwatch.inventory_report(store)` (printed by the CLI `regwatch status` without `--fetch`, cli.py:232), which reads the same stored records and is the natural tool for finding the damaged one, still raises. Measured on the head, with the same damaged record set the PR's tests use, written into the store file for one source:
| Damaged record | `inventory_report` on the head | `run_check` on the head | `run_check` on main |
|---|---|---|---|
| `5` (int), `1.5`, `true` | RAISED TypeError | returns a store-damaged row | RAISED TypeError |
| `"text"`, `[ {...} ]` | RAISED ValueError | returns a store-damaged row | RAISED ValueError |
| `{"sha256": 7}` | RAISED TypeError | returns a store-damaged row | RAISED KeyError |
| `{}`, `{"sha256": ["x"]}`, raw_bytes a string | returns | returns a store-damaged row | `{}` returns; the others RAISED |
`inventory_report` fails the same way on main; the diff does not touch it. Fix: reuse `_record_usable` there (and catch the error from `source_record`) so the status view shows the same named row, or narrow the title and docstring to "the check and check-file paths" and file `inventory_report` as its own card. The fix is two lines at regwatch.py:509 (`record = store.source_record(url) or {}` and `(record.get("sha256") or "")[:12]`).

## A second hole in the same promise (HIGH, measured; not a condition)
The docstring says a damaged record is "left exactly as stored: re-baselining it would erase a change detection". A stored JSON `null` for a source is read as "no record" (`source_record` returns None for a null value), so `run_check` reports `baseline`, exit 0, replaces the record with a fresh one and loses `first_seen`. Measured on the head: `status: baseline | exit_code: 0 | stored record now a dict: True | first_seen kept: False`. Main does the same. It is a damaged shape the PR does not list; I would add it to the follow-up with the status-view fix.
