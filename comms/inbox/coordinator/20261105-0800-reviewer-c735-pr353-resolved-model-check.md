## OBJECTIONS FIRST
1. F-C735-1 MEDIUM (a legitimate bind is refused under `--realpath` when the allowed root is a symlink): only `--repo-root` is resolved (`os.path.realpath`); `ALLOWED_ABSOLUTE_ROOTS` is compared as written. With the root `/x/fakehome` a symlink to `/x/real`: without `--realpath` a source `/x/fakehome/key1` is allowed; WITH `--realpath` the source resolves to `/x/real/key1`, which is not under the unresolved root, so it is refused ("outside the repository and the allowed roots") (probed with the root list pointed at a temporary symlink). The estate's one allowed root is `/home/spinner/.field-local/caller-keys`; a home whose `.field-local` is a symlink (common with dotfile managers) makes every caller-key bind refused at the deploy gate, and the operator's only way out is to drop `--realpath`, which is the option that stops a symlink inside the repository from reaching `/etc`. Fail-closed, but it removes the protection by pressure. Fix: resolve the allowed roots with the same function when `--realpath` is given, and pin both a symlinked root and a root with a symlinked parent.
2. F-C735-2 MEDIUM-LOW (the "a non-string source is never clean" contract covers one key): `judge(..., must_be_text=True)` is used only for service volume sources. Probed through `check_model`: `secrets: {k: {file: ["/etc/shadow"]}}`, `file: 5`, a config `file` that is a mapping, `driver_opts: {device: ["/etc"]}` and `device: 5`, `build: {context: ["/etc"]}` and `context: 5` all return NO problem (clean, exit 0, "every bind source is allowed"); `env_file: [{path: 5}]` is skipped silently; a service whose value is a string, a list or null is treated as an empty service. The header says a model whose shape it does not know (a bind source that is not a string "...") is exit 3 and "never read as clean". A resolved model from `docker compose config` never has these shapes, so the exposure is a model supplied by hand or by another tool; the gate then says "clean". Fix: `must_be_text` for every kind, and exit 3 for a service that is not a mapping.
3. F-C735-3 LOW-MEDIUM (lexical `..` before the link is followed): `source_problem` collapses `.` and `..` with `normal()` and only then calls `realpath`. Probed on a real tree: the repository holds `link_etc -> /etc`; the source `<repo>/link_etc/../x` is judged `<repo>/x` and allowed under `--realpath`, while the kernel resolves it physically to `/x` (the parent of `/etc`). The same with a link out of the repository: `<repo>/link_out/../data/f` is allowed. `docker compose config` itself cleans paths lexically (so a model from compose has no `..`), which makes this unreachable through `--run-compose`; for a model read from a file or stdin it is a fail-open under the option whose purpose is to follow links. Fix: call `realpath` on the original string (or refuse any source containing `..` when `--realpath` is given).
4. F-C735-4 LOW-MEDIUM (pins; 16 of 86 mutants survive, 8 real): not pinned: a newline or a NUL in a source (the literal-path refusal for either character can be dropped), a socket name inside the repository (`<repo>/docker.sock` is refused only by the socket rule), the normalisation of `--repo-root` (a trailing slash or `..` in the root: the mutant that leaves the root un-normalised refuses every source), `.envrc` as an allowed name (an `.env*` prefix mutant survives), UTF-8 as the file encoding (the default encoding would do under a UTF-8 locale), the message "every bind source is allowed" printed after REFUSED lines (a mutant prints it always), and the return code of `docker compose config` (ignored in a mutant).
