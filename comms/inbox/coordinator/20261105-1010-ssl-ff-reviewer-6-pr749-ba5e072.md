## Objections first (FORCE-O)
1. The "transport failure" branch still builds its reason from the exception text: `"sentinel unreachable — failing closed: {exc}"`. The new fixed-text reason (an unknown decision) is careful not to echo the body, but a transport exception's text (for httpx, usually a connection message; for a redirect or protocol error it can carry a URL) reaches the typed `ActionBlocked`. Pre-existing and outside this diff; the PR's own test only checks that the unknown-decision case does not echo the marker. LOW.
2. `governed` fails closed by RAISING `ActionBlocked`, and the new fail-closed verdict uses the `E.kill_switch` clause id and decision `BLOCK`. A caller that logs `clause_id` will see "kill switch" for what is really "the sentinel answered nonsense"; the reason text names it. Design (LOW).
3. Mutant G16 (a transport failure no longer blocked) survives these two test files; it belongs to the old code and is killed by other tests in the 328-test sentinel suite (I did not run it against the whole suite; unverified).
4. `_reasons_text` accepts a plain string as ONE reason (not joined by characters), drops non-string items from a list and gives an empty message for a missing or non-list `reasons`. All three behaviours are pinned exactly (G10, G11, G12, G14, G15 killed).
Steelman: before 52483052 only the exact strings "BLOCK" and "ESCALATE" raised; "block", "DENY", "ALLOW " or a body without a `decision` key was returned as if it were an allow, and `@governed` then RAN the function (a fail-open at the gate); a non-object body leaked KeyError or TypeError. Now every verdict that is not exactly ALLOW, BLOCK or ESCALATE is a typed `ActionBlocked`, with fixed text that does not echo the body, and the wrapped function is shown to never run (the `ran` list is asserted empty for 19 bad bodies). The second commit makes the BLOCK and ESCALATE messages survive odd `reasons` (int, null, dict, bool, list of ints, list with nulls, mixed).
