## Objections first (FORCE-O)
1. The CLI catches every `ValueError` from `store.append` and answers "error: event_type must not be blank". Measured on the head: `ledger append "\ud800x"` (a lone surrogate in the event type) and `ledger append action --agent-id "\ud800"` both exit 2 with that exact text, although the event type is not blank in either case; some other `ValueError` (an encoding error, probably) is being relabelled. Exit code 2 and nothing written are right (I did not verify nothing was written for these two), the message is wrong. LOW. Cause: `except ValueError:` has no message check, and store errors such as `SigningRequired` are `RuntimeError` so they are not affected.
2. The check is in `_append` (the writer shared by `append` and `append_for_caller`), so the offline CLI, the HTTP route and library callers are all covered; the HTTP route also has its own `strip()` check inside `run()`, so the 422 text is produced there and never reaches the store's ValueError (B8 and B10 killed).
3. The order of the new check relative to `_require_appendable(event_type)` is not pinned: moving it after (B4) passes the PR's file. With a blank type, `_require_appendable` presumably accepts it, so the result is the same; I did not run B4 against the whole suite (LOW).
4. The CLI message wording is not pinned (B7: the test asserts only `"error:"`), and the non-str branch of the store check (B3) is unreachable from the CLI or HTTP (both give a str), so it is untested defence (LOW).
Steelman: before the change a blank event type was sealed into the chain by the offline writer (`ledger append " "`), although `POST /events` refused it; now all three writers refuse, nothing is written (file bytes asserted unchanged), and the chain still verifies.
