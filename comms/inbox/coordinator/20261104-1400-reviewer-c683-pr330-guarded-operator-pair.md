OBJECTIONS FIRST
1. A table of "guarded routes" matched against a string the caller typed is not the same as matching the request that goes on the wire; any gap between the two sends a bearer key somewhere it is not needed, which is the thing this PR exists to prevent.
2. Moving the pair off reads only helps if every client does it; this is slice one. Other paths still add the pair to every request.
3. Three packages changed one mechanism; a regression in client flags (proxy environment, redirects, timeouts) would sit in the places that did not change.
4. Tests written against the same table the code uses can agree with each other and both be wrong.
