## Condition C1 (HIGH, measured on the head)
Anchoring `ai` removes a class of true positives for a tool whose job is to find AI accounts. `ACCOUNT_PATTERNS.search` on the head vs main's pattern `ai[-_.]` (main's pattern read from source, head measured by running the regex):
| Name | Head | Main (by regex reading) |
|---|---|---|
| openai-key | no match | match (`ai-`) |
| openai_worker | no match | match (`ai_`) |
| bob@openai.com | no match | match (`ai.`) |
| mlai_worker | no match | match |
| ai.worker, AI-Summarizer, x@ai.example, team_ai-x | match | match |
The PR comment names kai_nakamura, rai-chu and jsmith@thai.example as the false positives it fixes; it does not mention vendor-named accounts, and no test pins either result for them. An account named for the vendor but typed as a human or left untyped is now missed (an account typed `service`/`bot` still matches by type, and `agent|automation` still match anywhere). Fix: add vendor tokens explicitly (for example `openai`, `anthropic`, `gemini`, `copilot`) with tests, or record a decision to accept the narrower rule and pin it with a test for `openai-key`.
