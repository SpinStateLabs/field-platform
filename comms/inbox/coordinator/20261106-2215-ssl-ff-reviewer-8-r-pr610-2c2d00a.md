### C2 (MEDIUM, confirmed by running): three shapes still read as an EMPTY store although a stale flag is in the file, the fail-open the PR title says is closed
The writer always writes the keys `active`, `corpus_version`, `history`, `last_check`, `sources` (my probe, ss2_probe.py in my scratchpad, wrote a real flag with `StaleStore.mark` and read the file's keys). `_load` reads `data.get("active", {})`, so a file that exists but does not carry a usable `active` member loads as empty. With a real flag in the file:
- `active` renamed to `Active`, or to `flags`: loads, 0 active flags (the flag is ignored);
- the `active` key removed: loads, 0 active flags;
- a duplicate `"active"` key whose second value is `{}`: `json.loads` keeps the last one, loads, 0 active flags.
The unmodified correct file gives 1 active flag and 1 in `status()["active"]`. So `/pack` and `/staleness` would again answer as if nothing were stale for a schema-drifted or hand-edited file, which is exactly the harm S-2-24 describes ("an empty store would unblock evidence packs while a stale regulatory flag stands"). Files written before D4 had `active` (the PR says only `sources` and `last_check` were absent), so requiring it does not break them.
Fix: a file that exists must hold an `active` object (otherwise `StoreCorrupt`); refuse unknown top-level keys, or at least the case-variants of the known ones; load with a duplicate-key-refusing hook (the operators-file loader already has one, `_no_duplicate_keys` in operator_auth.py); tests for the three shapes.
