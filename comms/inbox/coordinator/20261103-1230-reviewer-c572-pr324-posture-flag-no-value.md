## OBJECTIONS FIRST
1. F-C572-1 MEDIUM-LOW (same class, five other variables, uncaught): `create_app` reads `FORCE_HYGIENE_WINDOW`, `FORCE_HYGIENE_BASELINE_WINDOWS` and `FORCE_GATEWAY_BYPASS_COOLDOWN` with `int(...)` and `FORCE_HYGIENE_BAND` and `FORCE_GATEWAY_LATENCY_BUDGET_MS` with `float(...)` and no `try`. A value that is not a number raises Python's own `ValueError` ("invalid literal for int() ... : '<value>'", "could not convert string to float: '<value>'"), which carries the value, and nothing catches it, so it reaches the startup traceback. Probed with a made-up canary in each variable through `create_app`: all five leak in the exception text and in the traceback; the two posture flags do not. The resolvers that DO catch it (`FORCE_TELEMETRY_WINDOW`, `FORCE_GATEWAY_SENTINEL_TIMEOUT`, `FORCE_GATEWAY_SAMPLE_EVERY`, `FORCE_TELEMETRY_RETAIN`) and the string readers (`FIELD_SENTINEL_URL`, `ANTHROPIC_BASE_URL`, `FORCE_HYGIENE_JUDGE`, `FIELD_DATA_DIR`) raised nothing and leaked nothing in the same probe. These five are numeric tunables, so a secret placed in one is a less likely slip than in a posture flag, but it is the same mistake (a shifted `${X}` in a compose file) and the same sink (a log). Fix: read them through one helper that catches `ValueError` and raises an error naming the variable only, and pin it with the same canary test. Not part of PR 324's stated change (C-502 names the posture flag), so it does not move the verdict.
2. LOW (the 8-character slice rule misses a short tail): the card's check is "any 8-character slice". A leak of the last seven characters of the value passes (mutant `=...<last 7 characters>`: SURVIVED all 447 tests); a leak of the first seven is caught only incidentally, by the older `"=enforce" not in msg` assertion, not by the canary. The canary is made up, so slices of 4 would cost nothing and close it. A length-only leak (`(N chars)`) also survives and is harmless.
3. LOW (the test covers the resolvers and `create_app`, not the process output): the startup path is `create_app` raising `InvalidPostureFlag`; nothing runs the server entry point and reads its stdout and stderr. The card asked for "the startup output". I did not run the entry point either (see below).
4. NOT A DEFECT: the PR changes six lines of `api.py`; the message loses the `{name}={value!r}` part and keeps the accepted values; the test renamed and tightened (`'enforce'` and `=enforce` must not appear); a new test over `FLAGS` and a test that every value in `BAD` is still refused.
