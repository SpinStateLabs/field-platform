THE 200 WITH A BAD SHAPE STILL REACHES THE CALLER AS A RAW LIBRARY ERROR CARRYING BODY TEXT. `LivenessClient._call` (field_agent/liveness.py:69) does `Heartbeat.model_validate(resp.json())` after the status check. Probes with the same hostile reply on 200: non-JSON body gives `json.JSONDecodeError` whose attribute `doc` holds the whole body (the marker is in the exception's `__dict__`; its message does not carry it); a JSON object of the wrong shape gives a pydantic `ValidationError` whose MESSAGE embeds a truncated repr of the values (marker visible, observed); invalid UTF-8 gives `UnicodeDecodeError`. 2. FEDERATION 200 BLOCK ECHOES UPSTREAM TEXT, UNBOUNDED. `FederationClient.cross` (federation.py:164-168) raises `CrossingBlocked(f"crossing {decision} by {clause_id}: {reasons}")` from the broker's JSON. The builder note leaves `_Unreachable.text` alone for the same reason; these are the SDK equivalents. MEDIUM (observed with a synthetic exception; real httpx messages vary and I did not enumerate them).

THE SENTINEL `check` COMMAND STILL PRINTS THE REPLY BODY. conformance_sentinel/cli.py:48-49: `typer.echo(f"error {resp.status_code}: {resp.text}", err=True)` on a non-200 reply, and line 52 prints the body on 200.
