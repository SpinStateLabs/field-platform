## Objections first (FORCE-O)
1. "Current behaviour is pinned" (the file's own words) means some quirks are now frozen. Two that a reader may not want frozen: `_csv_cell` leaves a value that starts with a space or a newline before the formula (` =x`, `\n=x`) untouched, and prefixes a plain negative number string (`-5`) with a quote, because `-` is a formula lead (it is on the OWASP list the test names, so the quoting of `-5` is the expected cost). Whether a spreadsheet evaluates ` =x` is not something I verified (I did not open a spreadsheet; the test freezes the code's choice). LOW.
2. `_domain_outcomes` treats an outcome it does not know, a missing outcome and a non-object row as ERRORS, counted exactly and listed up to 50 with their text cut at 200 characters; the count stays exact past the cap (D13 killed). The error text for an errored row is the kill-switch's own `error` string, which the C-19 comment calls a deliberate exception to "no upstream body is shown" (cut to 200); the test pins the cut (D9, D10 killed). That exception is a design choice stated in the code, not a defect.
3. `_drill_not_restored` accepts only a JSON `true` (a string "true" or the number 1 is a failure message), which is the safe direction for a drill (pinned: R1 killed). `_overview_digest` ignores only `generated_at`, sorts keys and falls back to `str` for non-JSON values; it is a change detector, not a security digest (SHA-256 is used and pinned by length 64; the md5 mutant O4 is killed only by the length check).
Steelman: these four helpers carry C-19 safety logic (a fleet halt reported as success while agents are still running) and a CSV-injection defence, and none was named by a test; every lead character, every outcome class, the caps and the digest's stability are now asserted, and the end-to-end export test proves a formula in `agent_id`, `event_type` and a payload `clause_id` comes out quoted while the JSON payload column is left alone.
