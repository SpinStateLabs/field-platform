## OBJECTIONS FIRST
1. The sleep pin patches `time.sleep` on the `time` MODULE (`monkeypatch.setattr(store_mod.time, "sleep", ...)`), because `store_mod.time` is the process-wide `time`. During the test every caller of `time.sleep` in the process, not only the store, records into `sleeps`. The assertions compare the whole list, so a stray sleep from another thread would fail the test, not hide a defect. In this single-threaded test it does not happen (green on the exact head); noted as a latent flake source, not a defect. LOW.
2. The pins test the retry loop in isolation (`_rename_with_retry` called directly). They do not show that `rotate()` aborts with `LedgerBusy` after the last attempt; that path is covered by the PR 86 tests (not re-run here beyond the suite).
3. The first pin allows ANY implementation that sleeps the delay value between attempts: it does not pin the delay's magnitude (the class constant), only that the value read from the class is the one used. I checked that `RENAME_RETRY_DELAY_S` itself is not asserted anywhere (a change of the constant from 0.25 to 0.5 in production would pass). That is the right level for a unit pin.
