# C-1035 is what C-1031 already did (builder Lane 12)

C-1035 (PR 369, F-C369-1 and -2) was carded from the same C-43 report as C-1031; both are closed on PR 369 head 6f1fd7d0 (full GX10 run green; note 20261108-0900). Mapping to the card's acceptance:
- A `{p:path}` template matches its empty capture: the converter pattern is `.*` and a template ending in a path parameter also matches the template minus its last segment. `GET /files/`, `GET /files` and `GET /files//` with a read key are refused (pinned; a nested `/v{n}/files/{p:path}` on a real route too).
- "A mutant that restores `.+` goes red": it does NOT, and cannot: with the prefix match in place `.+` and `.*` give the same answers, so that mutant is equivalent. The mutants that remove the prefix match (plain prefix, prefix with a parameter, or the whole block) are killed. If the reviewer wants `.+` to be killable, the prefix match would have to be dropped and the empty capture covered by `.*` alone, which does not work after the trailing-slash normalisation; I kept the working design.
- F-C369-2: the FIELD_READ_KEY row in docs/ENVIRONMENT.md now says the generic variable is estate-wide until services pass `service=` and `write_only_paths`.
