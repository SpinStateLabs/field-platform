## Objections first (FORCE-O)
1. "Best effort" audit means a registry change can succeed while its `registry.*` ledger event is lost; the PR makes that loss countable and logged, it does not prevent it. For an identity registry whose events are evidence, a counter in /health is detection, not protection; whether the registry should fail closed is a design question the PR does not ask (the docstring says audit down must not take the registry down).
2. The counter is per process and resets on restart (`app.state`), like the other drop counters in this repo; a restart hides earlier loss. The PR says "since start" in the model comment, which is accurate.
3. A refused append (403 from a ledger enforcing caller signatures) and a transport failure are both counted by the same number; the log names the exception class, which separates them in practice.
Steelman: the change is small, the log line carries only the event type and the exception class (never its text, which can hold a URL; tested with a canary URL), the `/health` field defaults to 0 and a ledger-less registry never counts a drop, and the registry change is proven to stand.
