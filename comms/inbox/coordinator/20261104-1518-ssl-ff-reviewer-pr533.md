## Objections first (FORCE-O)
1. The scan's second handler now prints `error: {exc}` for any ValueError or OSError from the run, the output write and the key read. For OSError the text carries a path (the operator typed it); for a ValueError from reading the private key as UTF-8 (a binary file given as `--key`), `UnicodeDecodeError`'s text names a byte value and position of the key file. One byte of a key file is not a leak that matters, but the config branch was deliberately written to print the class name only, and this branch does not follow the same rule (F2).
2. `except (ValueError, OSError)` is broad: an OSError raised deep inside `run_retro` or `write_outputs` (a full disk, a permission error on `--out`) is reported as a one-line error, which is the aim, but it is also the line a mistyped `--out` produces; none of these other paths is tested.
3. The "invalid JSON stays a ValueError" comment relies on `json.JSONDecodeError` being a ValueError (general knowledge, HIGH).
Steelman: the three crash classes the scout found (missing config file, config that is JSON but not an object, a key path that is a directory) each end in exit 1 with one line and no traceback, the config content is never echoed (tested with a marker), and a valid object config still scans.

- Public-safety scan: made-up markers only. HIGH.
