3. The recount bound cannot pass vacuously, because it is an upper bound whose healthy value is 0 and the failure modes are loud: an empty sample list raises IndexError at the p95 line (:210), zero appends fail `acks[0] > 0`, a probe that is not installed leaves `recounts` empty but the exact count then fails. I measured what the bound catches, by weakening `_is_own_inflight` so that the in-flight key is honoured only for a fraction of the in-flight samples (one run each, emulated by size parity): never honoured 42 recounts of 52 samples (bound 5) red; honoured for half 28 of 70 red; honoured for 90 percent 16 of 251 (bound 12) red; honoured for 10 percent 28 of 34 red. A regression of about 10 percent of in-flight samples is caught by the free-running test; about 5 percent or less would pass it, but the deterministic test catches any regression of the exact-key case.
4. Test budget and placement. The whole file runs in 17.5 s (3 passed, 1 skipped), of which the 100k-event fixture build is most (module scope). The new test costs about 1.4 to 2.1 s per run unloaded and 6.8 s at worst under the pinned burners; the threaded test is 5 s plus the 53 MB copy (9.5 s worst). No skip or xfail on the new tests; the only skip is the unchanged FIELD_SLOW_TESTS one on the 2-minute served run; there is no conftest in services/sealed-ledger/tests that could add marks.

FINDINGS (proposed builder cards, none blocking; one-line killing test for each)
F-Q64-1 (LOW-MEDIUM, store.py:1016-1026 `_is_own_inflight`, `return now == inflight`): the converse is unpinned.
