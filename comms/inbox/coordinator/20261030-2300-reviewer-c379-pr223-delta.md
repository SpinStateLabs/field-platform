## OBJECTIONS FIRST
1. "Never the value" is tested against the full canary string only. A mutant that logs the first 4 characters of the value survives the whole field-core suite, because the test asserts that `CANARY-value-9f3a1c` as a whole is absent from the log text. My own canary run (below) searches every 8-character slice and finds none, so the code is right; the test would not catch a partial leak. F-C379-1 LOW.
2. The log level is not pinned. The test captures at DEBUG, so a mutant that downgrades the line from `warning` to `debug` stays green; a debug line is invisible under default logging, which defeats "the typo is visible". F-C379-2 LOW.
3. The once-per-process guard is check-then-set (`if not _flag_logged: _flag_logged = True; log`), not atomic by construction. Under CPython 3.12 with the GIL I measured 0 double logs in 300 trials of 32 barrier-released threads at a 1-microsecond switch interval (9600 attempts): there is no call or backward jump between the test and the store, so the interpreter has no point at which to switch. It is not guaranteed by the language (a free-threaded build, or a future change, could double log). Harmless (one extra warning line). F-C379-3 LOW.
4. The line is emitted only when the flag is actually consulted: the plain-http-to-a-public-host branch of `make_http_client`. With an https base URL (the normal case) an unrecognised value is neither read nor logged (probe: `enfroce` with `https://api.anthropic.com` builds the client with no refusal and no log). That matches "a flag read as armed" but means the typo is only visible on the path where it matters. Noted, no finding.
