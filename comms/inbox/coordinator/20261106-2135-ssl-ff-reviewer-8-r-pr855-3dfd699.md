## Condition
### C1 (MEDIUM, confirmed by running): `--services` and `expected_services` REPLACE the stage's list, so they can watch fewer services than the stage requires
`_arm` uses `expected = spec.services if self.expected_services is None else self.expected_services`, and the constructor accepts any non-empty subset of the eight names. Probes (p855_probe.py in my scratchpad, fake driver, records bound to a sha):
- CLI `plan --stage 3 --go-sentence go --build-sha <sha> --services registry` prints `stage 3 may start ... services: registry` (exit 0); Stage 3 should watch all eight.
- CLI `plan --stage 2 ... --services registry` is accepted: Stage 2's REQUIRE is armed on the KILL-SWITCH, which this list no longer contains.
- A live Stage 3 run with `expected_services=("registry",)` and a baseline that names only `registry` returns `completed` with all three steps; the same run with the default list and that baseline returns `aborted_rolled_back` (health failure), as RT-832-R2 wanted.
So the S2-2 knob that was added to close R2 can undo it: whoever builds the driver, or types the command, can shrink the abort check to one service and the stage still completes.
Fix: the override may add names but never drop one of the stage's own (`expected = set(spec.services) | set(override)`), or refuse an override that lacks any `spec.services` name (`services_narrower_than_stage`); test both CLI and `Controller`.
