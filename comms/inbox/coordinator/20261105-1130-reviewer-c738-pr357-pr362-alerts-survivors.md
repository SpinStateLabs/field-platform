## OBJECTIONS FIRST
1. F-C738-1 LOW (a retry-class branch is untested): in `alerts._post_once` the clause `except (OSError, http.client.HTTPException)` is the only handler for `http.client.BadStatusLine`, `IncompleteRead` and the like, which are `HTTPException` but NOT `OSError`. PR 362's parametrised table uses `http.client.RemoteDisconnected`, which is both (it derives from `ConnectionResetError` and `BadStatusLine`), so a mutant that drops `HTTPException` from the tuple survives (SURVIVED, mutant P8). Without it a `BadStatusLine` would escape `_post_once` and be caught only by `_attempt`'s catch-all as `error`, not retried (the code comment says "never past send()'s contract"), so the retry behaviour for a garbled status line changes silently. Fix: add `http.client.BadStatusLine("x")` and `http.client.IncompleteRead(b"")` to the network-failure table.
