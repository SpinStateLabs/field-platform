## Objections first (FORCE-O)
1. The workflow puts Anthropic organisation identifiers into a public file: the organisation id, workspace id, federation rule id, service account id and environment id (ssl-fp-role-session.yml, the token exchange and session steps), plus five platform agent ids. They are not credentials; the safety of the design rests on the federation rule (claimed in the workflow comment to accept only runs of this repository on refs/heads/main), which is configured outside this repository and which I cannot verify (not in source). PROTOCOL.md's public-files rule names "estate address, flag value, build id, deploy status, credential"; whether these identifiers count is Don's ruling. Agent ids and an older environment id were already public on main in tools/start_role_session.py; the organisation, federation-rule and service-account ids are new.
2. `permission_policy: {type: always_allow}` with bash, write and edit enabled (agent.md of each role, the comment says "pattern A is cooperative: the FIELD checks in the prompt are the checkpoint"). The agents are given unprompted shell access whose only restraint is their own prompt; the manifests' "never" action is "merge pull request", which a prompt-level agent can still do through bash with the repository token. This is an authority decision for Don, not a defect I can test.
3. The workflow is `workflow_dispatch` with `id-token: write`: anyone who can run workflows can start sessions that bill the shared workspace, bounded by the budget input (up to four digits of cents) and, if the rule is right, by the branch condition.
4. 21 files in one PR (5 manifests, 10 agent files, a workflow, a PowerShell tool) is a large review surface for one verdict; I validated what can be machine-validated and read the rest, but did not review the role prompts line by line.
Steelman: the structure follows the repository's own pattern (manifest, agent, skill per role); each manifest validates; the workflow validates its inputs with anchored regexes in `env:` (no input is interpolated into a shell command line), writes the token via `::add-mask::`, and uses no stored secret; key_intake.ps1 prints a fingerprint and byte count, never the key, and clears the clipboard.
