## Objections first (FORCE-O)
1. A NUL in `--out` still ends in a traceback, but not in the hazard the PR fixes. Measured on the head: `decommission ... --out "x\0y.json"` exits 1 with a ValueError ("stat: embedded null character in path") raised at option-parse time inside typer's Path conversion (`os.stat`), BEFORE the command body; the engine was never called (the fake engine's call list is empty), so no estate change happened and no report was lost. PR 715 (incident-replay) avoided the same parse-time failure by declaring the option as `str`; this PR keeps `Path`. The `except OSError` in `_write_report` cannot see it. LOW.
2. The out-less path is untested. Both `provision` and `decommission` now print the payload through `(typer.echo(payload) or True)` when no `--out` is given, an idiom that works only because `typer.echo` returns None. Mutants E14 and E15 (print nothing when there is no `--out`) survive all 11 tests: no test runs `provision` or `decommission` without `--out` and checks the report is on stdout. That is the common call. LOW to MEDIUM (it is the default output of an estate-changing command).
3. The error line is only half pinned: the tests assert "error: could not write" and the exception class, but E5 (the exception's own text added), E7 (the path no longer named) and E6 (written to stdout) all survive. The docstring promises "class only". LOW.
4. `MAX_TTL_DAYS = 1_000_000` is the cap and the test imports the constant, so it adjusts itself: E18 (999,999) survives; E17 (2,000,000) and E16 (no cap) are killed by the literal over-limit inputs (1,000,001 and larger), so the upper side is pinned, the exact boundary is not. The comment's reasoning is checkable and checks out: 1,000,000 days from now is year 4700 or so, below 9999, and the test asserts `.year < 9999`.
5. Exit-code design: a completed transition whose report file cannot be written is exit 4, a failed transition keeps 1, a sweep with findings keeps 3 even when the write fails (pinned: E11 killed). A caller that treats any non-zero as "the estate change failed" will misread 4: the transition DID happen. The exit-4 text says so only in the docstring and the stderr line ("the report is printed above").
Steelman: provision, decommission and sweep write their report file after the estate was changed; before the change a missing directory or a directory path raised an OSError traceback and the only record of what had been done (the report) was lost. Now the report is printed to stdout (the JSON, not the Markdown, for sweep), the failing class and path go to stderr, and the exit code is 4 unless something more important (a failed transition, findings) applies; `--ttl-days` above one million is a usage error (exit 2) before any call, instead of an OverflowError after the mint was planned.
