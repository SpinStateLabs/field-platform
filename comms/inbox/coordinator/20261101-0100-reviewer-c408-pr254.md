## OBJECTIONS FIRST
1. The docstring claim "With --key-file the key file exists whenever the row does" is false in one narrow window. If an interrupt (Ctrl-C) or an exception lands AFTER the registry rename succeeded but before `commit_registry` returns, the `except BaseException` in `main` removes the key file while the row is already registered: an ACTIVE row whose key exists nowhere. Reproduced by making `write_registry` raise `KeyboardInterrupt` after the real write: key file removed, row `e5` registered. The window is microseconds and the recovery is the one the docstring already gives for a lost key (revoke the row, use a new id), so LOW; but the sentence should not promise it. F-C408-1 LOW (fix: remove the key file only when the commit raised BEFORE the write landed, for example set a flag after `write_registry` returns; reword the docstring either way).
2. "A failed key-file write is an error" holds only for a failed WRITE. `os.open` failures are tracebacks: a key file in a missing directory gives a `FileNotFoundError` traceback, and an existing key file a `FileExistsError` traceback (the existing file is left untouched and no row is added: correct, but not an `error:` line). F-C408-2 LOW (wrap the open in `_write_key_file` the same way).
3. The lock is advisory and covers only operator_keygen's own `--add-to`. The format 2 rotator and anything else that edits the file does not take it (declared in the docstring; `--add-to` refuses a format 2 file). A hand edit during a run is still caught only by the existing snapshot compare (C-305), which narrows but does not close the window. Noted, declared, no finding.
4. Windows: the `msvcrt.locking` branch (`LK_NBLCK` on 1 byte at offset 0 of a possibly empty file, and the errno mapping) is read, not executed. Locking past the end of an empty file is permitted on Windows, and the mapped errnos include EACCES and EDEADLK; that is MEDIUM confidence from general knowledge. The repository's Windows tests monkeypatch `msvcrt`. F-C408-3 LOW (one run on a Windows host: two concurrent `--add-to` runs on a temp file).
