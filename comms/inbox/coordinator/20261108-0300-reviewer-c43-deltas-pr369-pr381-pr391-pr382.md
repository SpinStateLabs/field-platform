## OBJECTIONS FIRST
1. F-C369-1 MEDIUM-LOW (PROVEN; PR 369: a `{param:path}` write-only template misses the empty capture): `authn._write_only_matcher` turns `{p:path}` into the regex `.+` and normalises the path with `rstrip("/")` before matching. Starlette's `path` convertor accepts the EMPTY string, so `/files/` is a route hit with `p=""`; normalised it is `/files`, which the pattern `/files/.+` does not match, so the request is treated as not write-only and a read key is accepted. Probed with `write_only_paths={"/files/{p:path}", ...}`: `GET /files/a/b/c` read key 401 (correct), `GET /files/` read key 200 (the handler ran). The same through a redirect: `/files` (307 by the router) then `/files/`. The mutant that changes the pattern to `.*` (the natural fix) SURVIVES the 1234-test field-core suite: no test covers the empty capture. Scope: no service passes `write_only_paths` or `service=` yet (grep of `services/*/src`: every service calls `install_authn(app)`), so nothing shipped is exposed today; the hole is in the mechanism a later PR will wire. Fix: `.*` for `:path` templates and match the stripped form of a template that ends in a path parameter; pin `GET /files/` and `GET /files`.
2. F-C369-2 LOW-MEDIUM (PR 369, scope when wired): with `FIELD_READ_KEY` set and nothing else, every service that calls `install_authn(app)` with the DEFAULT arguments (all 14 do) accepts the read key on every GET it serves, because no service lists a write-only path and none names itself (`read_key(None)` reads the generic variable). That includes GET routes that fetch third-party sources or build evidence (`/pack`, `/pack.html`, `/api/events/export`, `/retention/check`, `/verify`; I did not classify each as a pure read). The ENVIRONMENT.md row says "not wired in any service yet" for the per-service variable only; it does not warn that the GENERIC variable already takes effect everywhere. Setting it today is therefore an estate-wide decision with no per-route review behind it. Fix: say so in the row, or make the generic variable apply only to services that opt in.
