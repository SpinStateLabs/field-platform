## Conditions
### C1 (MEDIUM, confirmed by running): a counter that DECREASES passes the window, and a decrease is what a restart looks like
`evaluate_window` relies on `_increases`, which flags only a rise. The counters are in-process (`dropped_unauthenticated_records` is a module global, operator_auth.py:1575), so a service restart inside the window resets them to 0. Probe (g18_probe.py): before 5/3, after 0/0, 10 hours apart, every service: `evaluate_window` returns no problems (CLEAN). Drops that happened before the restart are invisible, and the PR's own text says "Equal counters (or a decrease) over a long enough window pass". Stage 1 is the window in which the eight services are recreated and watched, so a service that restarted (crash loop) and lost its counter is exactly the case to refuse.
Fix: treat a decrease as not clean ("counter went down: the service restarted, the window cannot be judged"), with a test.

### C2 (MEDIUM): the G18 record carries no evidence of the window, and the default window length is zero
`--min-hours` defaults to 0. Probe: two snapshots one second apart, no `--min-hours`, `--records ... --build-sha abcdef1234`: exit 0 and the row written is exactly `{gate: G18, kind: gate, ok: true, sha8: abcdef12}` (plus a timestamp). That row is identical to the row for a 24-hour window, and PR 838 (G25) makes this row the Stage 2 gate. The red-team note the PR cites asked for a duration to be enforced; it is only enforced if the operator remembers the flag, and nothing in the record shows what was judged.
Fix: write the window span (hours, from the two `taken_at` values) and the service count into the row, and set a non-zero default `--min-hours` (or make it required with `--records`); the runbook should state the required length (it states none today: it says "a clean Stage 1 window with its evidence", runbook line 1472 on main).
