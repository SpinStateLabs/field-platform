## Objections first (FORCE-O)
1. "Do NOT re-run rotate" is the right instruction, and the code earns it: a failed `--anchors` write now happens AFTER the result is printed (stdout), exits 1, and prints the anchor JSON to stderr for off-box storage. The tests pin that order (the result is on stdout first; the rotated file exists; the anchor is on stderr). What nothing can pin is that an operator reads stderr: the anchor is the off-box proof (the whole point of rotation anchors), and exit 1 plus a SUCCEEDED rotation is a state a wrapper script will probably treat as "rotation failed" and retry. The message says not to; scripts do not read messages (design risk, MEDIUM; the previous behaviour, a traceback after a completed rotation with no anchor printed, was worse).
2. `_safe_url` removes userinfo, query and fragment: measured on the head, `http://alice:hunter2@127.0.0.1:1/x?token=SECRET#frag` becomes `http://127.0.0.1:1/x`, and unparseable URLs become `<unparseable URL>`. That is a good answer to the same class of leak I measured in PRs 638 and 663. Two details are unpinned: the query strip (mutant A3 keeps `?query`) and the port (A4 drops it); no test sends a URL with a query or checks the host:port in the message. LOW.
3. The unreachable line still prints `{exc}` (the httpx exception text) next to the sanitised URL. The test proves `alice` and `hunter2` are absent for a connect failure to `127.0.0.1:1`; an httpx error whose text embeds the full URL (some do for redirects or protocol errors) is not tested (LOW, not measured).
4. `--anchors` changed from `Path` to `str` so that a NUL byte does not fail at option parsing (A21, the old `Path`, is killed by the NUL test). The same trick was used in PR 715; PR 745 (lifecycle CLI) did not, and still shows a parse-time ValueError for a NUL in `--out`.
5. A served 2xx with a non-JSON or unexpected body is exit 2 with a one-line message and the body is not echoed (asserted for rotate and for `hold place`); the generic helper `_served_or_exit` now uses the same guard (A14 killed), so every served mutating verb (hold, retention and so on) gets it, not only rotate.
Steelman: before the change a failed anchor write after a COMPLETED rotation raised a traceback and the result (and the anchor) was lost, a non-JSON 200 or a malformed `FIELD_LEDGER_URL` was a traceback, and a URL with credentials was echoed whole in the error. Now each is one named line and exit code, the result is printed before the anchor write, and the URL's userinfo is never printed.
