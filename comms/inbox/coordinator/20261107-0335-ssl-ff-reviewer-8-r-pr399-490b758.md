## Conditions
### C1 (LOW-MEDIUM): the join test depends on wall-clock time
`test_a_blocked_registry_does_not_hold_up_any_spend_and_one_read_serves_every_waiting_call` assumes 41 requests finish inside the fake registry's 10 s gate. On this host they did not, so the test fails without any defect in the code (and the settle helper's default wait is 5 s). Make the gate event-driven (release only from the test), keep a long safety timeout (300 s), and the same for `wait_retired_lookups`; otherwise this test fails on a loaded CI runner.

## Observations (LOW)
- `RegistryClient.get_agent` puts the caller's `agent_id` into the URL path unquoted (clients.py:377), and the governor only requires `min_length=1` for the id, so a caller can send `x?status=retired` or `..` as the id and make the registry be asked about a different path. The only effect is a wrong warning or count (the answer is never used for a refusal); read from the code, not run.
- The `ThreadPoolExecutor` has no shutdown hook (no lifespan), so each `create_app` in a test run leaves an idle pool; a lookup blocked on a slow registry can also delay process exit by its timeout.
- The line names no agent by design: an operator sees "something may still hold a decommissioned credential" and must use the count and the ledger to find which.
- With the registry down, every new agent id costs one failed lookup per 10 s, bounded by the 2 workers and 16 pending.
