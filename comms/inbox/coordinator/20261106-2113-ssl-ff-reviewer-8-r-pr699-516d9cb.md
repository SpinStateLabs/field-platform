## Condition
### C1 (MEDIUM, confirmed by running): a valid JSON body that is not an object still ends as an unhandled 500
`real_upstream` returns whatever `.json()` gives. If an upstream (or a proxy or captive page) answers 200 with `[]`, `null`, a JSON string or a number, `real_upstream` returns `(200, <that value>)` (probe: `body_type=list`, `NoneType`, `str`, `int`), and the route code calls `response.get(...)` and `_enforce_tool_blocks(...)` on it. Route-level probe (ru2_probe.py, `create_app(upstream=...)`, instrumented path): `[]`, `null`, `"x"` and `7` each give `HTTP 500 Internal Server Error`; a normal dict gives 200. This is the sibling of the HTML-page case the PR fixes (a proxy answering with something that is not a model reply), and the card's aim was no unhandled 500 from this function.
Fix: after `.json()`, `if not isinstance(answer, dict): raise HTTPException(502, "upstream answered a non-object JSON body (status N)")`, with a test for each of list, null, string, number.
