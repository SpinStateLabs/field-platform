# Q-02 reviewer report: docs/adr contradictions with merged code (main b1872ee)

VERDICT: `docs/adr/` holds three ADR packs only (02 Conformance Sentinel, 07 Compliance Crosswalk, 10 FORCE Gateway; 54, 80 and 77 lines). ADR-0071, 0072 and 0074 are not in this directory (they appear only in STATE.md and the crosswalk README), so they could not be audited here. Two statements in ADR 10 are contradicted by merged code; ADR 02 has one arithmetic slip and a gate mismatch; ADR 07 carries a stale status.

OBJECTIONS FIRST
1. ADRs are design records dated at their decision; code that later changed the design makes the ADR out of date, not wrong at its date. The finding is that no later note says so.
2. ADR 02's "Measured PoC" figures come from a live ledger of August 2026 that is not in the repository; I checked only their internal arithmetic and the scorecard evidence that is in the repository.
3. I read the three packs through their decision, guardrail and measured-result passages; not every paragraph.

ASSUMPTIONS
1. `docs/adr/ADR_Pack_02_Conformance_Sentinel.md`, `ADR_Pack_07_Compliance_Crosswalk.md`, `ADR_Pack_10_FORCE_Gateway.md`; evidence `docs/capstone-evidence/sentinel-scorecard-s2.json` and `.md`. [HIGH]

REASONING
1. MEDIUM, F-Q02-1: ADR 10 (line 61) "The Gateway is an observer ... the proxy fails open: its own failure bypasses it rather than blocking production calls"; guardrail row (:63) "On proxy fault, latency over budget, or judge spend at cap, the Gateway drops to bypass mode". Since v1.2 F1 the code has an enforcing mode: with `FORCE_GATEWAY_ENFORCE=1` `/v1/messages` requires `x-field-agent-id` and `x-field-token` (401), asks the sentinel (403 on BLOCK, 503 when the sentinel is unreachable) and strips out-of-scope `tool_use` blocks (`force_gateway/api.py` comments: "identity and authority FAIL-CLOSED, before the passthrough exemption and before any bypass window - the Gateway's own trouble may drop instrumentation, never enforcement"). The ADR's fail-open guardrail still holds for the instrumentation (bypass window), not for enforcement; the ADR does not say so, and GB10 and Fly run `enforce` (descriptors). [HIGH]
2. LOW, F-Q02-2: ADR 10 (:59) lists "control/governance (the Gateway takes no autonomous action)" as a lower-priority risk. With enforce on, the gateway refuses calls and removes tool-use blocks: an action. Same cause as F-Q02-1. [HIGH]
3. LOW, F-Q02-3: ADR 02 "Measured PoC" (line 51): "136 live verdicts - 73 allow / 63 block ... blocks = 1 out-of-scope real-order attempt, 57 expired-authority, 2 unregistered-agent, 2 missing-manifest". 73 + 63 = 136 holds, but 1 + 57 + 2 + 2 = 62, not 63: one block is unaccounted for in the breakdown. The underlying ledger is not in the repo, so I cannot say which figure is wrong. [HIGH on the arithmetic]
4. LOW, F-Q02-4: ADR 02 (:49) "PoC -> pilot gates (ratified 2026-08-29): catch >= 97.8% ... false-block < 1.6%". The seeded scorecard of the same date records its own gates `catch_min 0.95`, `false_block_max 0.02` (sentinel-scorecard-s2.json `meta.gates`; the .md says "proposed; ratified at PoC exit" and "NOT ADR 02's pilot->production gate"). The ADR text (:53) says the scorecard "clears >= 97.8%" and "< 1.6%": numerically true (40/40, 0/53) but the scorecard evaluated against 95% and 2%. The same document also reports a combined false-block of 11.7% (7 paraphrased-conforming would-block) that fails 1.6%; the ADR mentions the 7/7 probes. Two sets of gate numbers for one milestone. [HIGH]
5. LOW, F-Q02-5: ADR 07 header says "Status: design record, pre-build - 2026-08-29"; the service is built and deployed (`compliance-crosswalk` on both estates, 13 controls, 16/52 cited per R-16). Its statement (:47) "every mapping and every evidence-pack claim cites manifest clause, control ID, and the regulation version/effective date" matches the code only partly: citations carry `reference + source_url + retrieved` (a retrieval date), not a regulation version or effective date field (mapping.py `Citation`, :76-92). ADR 07's guardrails (signature is the action; stale flag blocks regeneration; named signer) match the code (R-16). [HIGH]
6. Consistent (checked): ADR 02's fail-closed and log-only shadow descriptions match `mode.py` and `engine.py` (R-11, C-157); ADR 07's "no pack ships without a named signer ... stale blocks" matches `evidence_pack.py` (ValueError on an empty signer, `StalePackError`, no override parameter). [HIGH]

CONCLUSION
Add a dated "Superseded in part" note to ADR 10 (enforce mode, F1) and a status update to ADR 07; reconcile ADR 02's 62/63 and the two gate sets; commit ADR-0071/0072/0074 to this directory if they are meant to be audited with the others.
