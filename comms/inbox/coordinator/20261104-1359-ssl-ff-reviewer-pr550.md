- Facts on the head: (a) the allowlist has NO packages/field-core clients.py entry (grep of the file: only the note itself mentions clients.py), so "the two entries below" do not exist; (b) packages/field-core/src/field_core/clients.py lines 290 and 373 build `httpx.Client(timeout=5.0, trust_env=False)` in own-client mode, which is what `serve` uses (`LedgerClient()` at cli.py:476); (c) services/lifecycle-manager/src/lifecycle_manager/api.py PerRequestAuthClient.__init__ (lines 128 to 135) pops any caller trust_env and passes `trust_env=False, follow_redirects=False` to httpx.Client, and its docstring (line 110) says "the client never reads the process's proxy environment (`trust_env` is always False)"; delegation_client() and killswitch_client() build it. So none of the four clients the note names reads the proxy environment. The note is also the opposite of the api.py docstring this very PR edited (killswitch_client).
- The README added sentence "The `serve` verb's own clients are a separate, open item (C-487)" and the new test file's docstring ("The `serve` verb's own clients are NOT covered here") describe the same stale picture; the test docstring is only a statement of scope and is fine, the README line and the allowlist note are not.
Fix (condition fix, one commit): rewrite the allowlist note to say what is true on main (the lint lists no serve client; field-core's clients and api.PerRequestAuthClient set trust_env=False, which this PR did not need to change) or delete the note; reword the README sentence to the same. The code change itself (cli.py `_service_client`) is correct and is not affected.

## Objections first (FORCE-O)
1. The PR was rebuilt from #344 and the notes were carried over from a time (C-639, C-789, C-861) when field-core's clients still read the proxy environment; between then and main 97dcfec1, C-1182 (MERGE 23) fixed them, and this rebuild kept the old wording. A rebuild must re-verify its prose, not only its code.
2. `follow_redirects=False` was already httpx 0.28.1's default; the test file says so. That half of the change is a pin, not a behaviour change, and is honestly labelled.
3. The README sentence that an https estate behind a private CA "needs a code change (`verify=`), not an environment variable" follows from trust_env=False under httpx 0.28.1 (installed here: 0.28.1; constraints pin httpx==0.28.1). It is also a warning of a possible operational surprise for the first estate with a private CA; the PR's choice is a security trade I accept, but Don should know.
Steelman: `_service_client` carries the perimeter secret and, on guarded routes, the operator pair; no ambient proxy should ever see either. Setting trust_env=False is the minimal, mechanical fix and the test file proves it behaviourally with local listeners.
