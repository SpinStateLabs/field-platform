## Objections first (FORCE-O)
1. A failed auto-kill is now reported, not retried: the orphan stays active, is ledgered as an orphan, and shows "AUTO-KILL FAILED (class)" in the report. Nothing in the sweep re-attempts it; the operator must read the report or rerun. For a kill-type action that is the stated design ("reported as a step, never hidden"), but an unattended scheduled sweep (FIELD_LIFECYCLE_EVERY) leaves a still-active orphan until the next tick (not tested; LOW).
2. `_Unreachable.text` still carries the full exception text (`transport error: Name: <message>`), which can hold a URL. The new `kill_error` field uses only the class name, and the test proves the host and message do not reach the JSON or Markdown (ReadTimeout case). Other users of `_Unreachable.text` elsewhere in the engine were not audited here (MEDIUM, not checked).
3. The `status != 200` rule treats any non-200 answer (a 202, a 204) as a failed kill with "HTTP <status>". Matches the previous `== 200` rule; only the failure is now visible.
4. `_try` catches `Exception`, so a programming error inside the kill-switch client call is reported as an "unreachable" class name rather than propagating; the class name keeps it diagnosable.
Steelman: before the change one transport error on the first orphan raised out of `sweep`, so no orphan was reported or ledgered and the remaining orphans were never killed; now every orphan is reported and ledgered and the others are still killed (test: orphan-a fails, orphan-b is killed and both are ledgered).
