## Objections first (FORCE-O)
1. The refusal matches the LITERAL marker with whitespace and case tolerance only. Measured on the head (`_DELIMITER.search`, and `injection_screen` for the screen): `<<<ACTION-END>>>` (hyphen), `<<<ACTION_END>>` (two closers), fullwidth `＜＜＜ACTION_END＞＞＞`, a zero-width character inside the word, `<<<ACTION__END>>>` (double underscore), `<<<END>>>` and an HTML-escaped form are NOT matched and the screen returns None for each; a tab, an NBSP or lower case ARE matched. None of these is the exact marker the prompt uses, so none closes the block syntactically, but a language model may read a near-forgery as an end marker. The claim in the code ("the literal markers") is accurate; the protection is a fence against the exact text, not against look-alikes (HIGH measured; MEDIUM that a model would be fooled by the look-alikes; I did not test a model).
2. Scope entries and the agent id are refused only in `AnthropicJudgeClient.judge`, not in the screen; the engine screens only the action. The PR says so, and the judge refusal is the second line (pinned: D4 and D5 killed). The `judge` class is marked `# pragma: no cover` ("declared-untested without keys") yet the new tests exercise it with a fake client, which is better than before.
3. Refusal means JudgeError, which the engine turns into an escalation (the test accepts ESCALATE or BLOCK). A caller that retries on JudgeError would retry forever against the same input (not checked; LOW).
4. The end-to-end test hands the engine a forged action and asserts zero upstream posts, but it imports `tests.test_judge._arm`, so it only runs from services/conformance-sentinel as the rootdir (my first run from the repo root would have failed to import it; run from the service directory).
Steelman: the untrusted action sits between two fixed markers; before this change an action (or a scope entry, or an agent id, which the screen never saw) could contain the closing marker and put instructions after the data block. Now the screen and the judge refuse all three inputs before any model call, with whitespace/case variants covered.
