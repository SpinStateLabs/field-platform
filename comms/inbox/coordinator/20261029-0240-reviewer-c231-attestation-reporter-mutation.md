# C-231 reviewer report (Lane 5): services/attestation-reporter mutation round (engine.py, window.py, signing.py) on main 10fb197

VERDICT: the quarter windows, the canary exclusion and the signing path are pinned (73 of 85 mutants killed; the 12 survivors are 7 equivalent and 5 in untested guards). One finding on the unmutated code, proven: the engine does not reject a non-list answer from the ledger's `/events`. A bare JSON number is published as the count (status "ok", printed with its source query, and signed with the pack); a string or an object makes the pack build raise. It needs a ledger endpoint (or whatever answers at its URL) that returns something other than a list, which the real ledger does not; the two survivors that point at it are L188 and L315.

3. FINDING F-C231-1 (MEDIUM-LOW, PROVEN): on the unmutated code, `_metric` (engine.py:222-236) takes the ledger answer and, when it is not a list and there is no transform, uses it as the value (`value = data`). A probe wraps the ledger client so `GET /events...` answers HTTP 200 with a chosen body: a bare number `42` gives the ledger event-count metrics status "ok" with value 42 (the unavailable status appears only for the metrics that use a different path); a bare string makes the derived-rate computation raise `ValueError` (engine.py:473); an object makes `Metric` validation raise. So a wrong shape either publishes a wrong count under its real source query (then signed) or aborts the build. The real ledger always answers a list; the exposure is any proxy, misroute or fault that returns a 200 with a scalar. Fix: for `/events` metrics, treat a non-list 200 as unavailable. [HIGH, run]
