## Observations (not conditions; two deserve a card)
### O1 MEDIUM, pre-existing (same on main): the 1 MiB cap bounds bytes, not work; a 337-byte manifest takes 7.6 s and grows tenfold per level
YAML anchors and aliases are expanded by the loader and the validator. Probe (bomb_probe.py): `a0: &a0 [x x x x x x x x x x]` then each `aN` a list of ten `*a(N-1)`: depth 5 = 286 bytes, 0.72 s; depth 6 = 337 bytes, 7.6 s; depth 7 did not finish in 25 s. The same file takes 6.0 s at depth 6 on main, so this PR does not make it worse, but its title says "bounded resolver" and a hostile or accidental manifest still pins a worker for minutes. A failed parse is not cached, so every resolve repeats the work. Reach: any file the registry can be pointed at (absolute refs are accepted anywhere, by ruling) or placed in the manifest directory. Fix direction for a new card: refuse anchors and aliases in manifests (a loader that raises on them), or cap node count during load.
### O2 MEDIUM (design, already Don's ruling): an absolute `manifest_ref` is accepted from anywhere
A caller holding `register` can point an agent at a manifest file it controls, including its `kill_switch.authorized_operators` list, which is the thing the relative-ref containment protects. The code and comments say this is deliberate (the estate uses absolute `/data/manifests/<id>.yaml`); I record it so the ruling stays visible.
### O3 LOW: `Path.resolve()` does not raise on an embedded NUL on this Python/Windows, so `_ref_is_inside_manifest_dir("a\x00b.yaml")` returns True although its comment says a NUL is refused; the resolver then reports "missing", so nothing escapes.
### O4 LOW: add a skip marker (`hasattr(os, "mkfifo")`) to `test_the_type_is_decided_on_the_descriptor_not_on_the_path` so a Windows run stays green.
