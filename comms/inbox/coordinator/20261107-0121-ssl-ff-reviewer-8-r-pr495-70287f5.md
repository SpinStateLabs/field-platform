### C2 (MEDIUM, confirmed by running): values that switch the detector off are accepted
The PR's own harm is "a NaN band made drift never alert". Judge scores are 0..1 (hygiene_judge.py:38-39), so any `FORCE_HYGIENE_BAND` of 1 or more can never be exceeded (`abs(mean - baseline) > band`, drift.py:91). Probe (create_app with the environment set): `FORCE_HYGIENE_BAND=1` gives band 1.0, `1e300` gives 1e+300 (accepted); `FORCE_HYGIENE_WINDOW=999999999999` gives that window (a window that never fills, so no score is ever judged); `FORCE_GATEWAY_LATENCY_BUDGET_MS=1e300` gives a budget that is never breached (the bypass never engages). All three are finite, in range by the PR's rules, and silently disable the check they tune. Fix: an upper bound that keeps each knob meaningful (band < 1, for example 0.5; window and baseline windows a documented maximum; latency budget a documented maximum), with the same fall-back-to-default rule and tests at the new edges.
