## Objections first (FORCE-O)

A symbol cite is only as good as the symbol: if a function is renamed, the cite rots silently, and no test here checks that the named symbols exist (the new test checks only that no line cite is present). The PR 540 test (a different PR) does check symbol existence for its five cites; this one does not. LOW.
2. Some replacements are less precise than the line cite they replace ("module docstring", "the estate-client table"): a reader must search the file. That is the trade for stability, and it is stated in the test file.
3. The test scope is two files; the repository's README, runbooks and ENVIRONMENT.md carry other line cites (ENVIRONMENT.md deliberately, because tools/environment_anchors.py verifies its anchors).
Steelman: the old cites had drifted (the test docstring says about half; the PR text corrected itself from "21 of 23" to "about half" in the second commit), so removing them is a net gain for accuracy.
