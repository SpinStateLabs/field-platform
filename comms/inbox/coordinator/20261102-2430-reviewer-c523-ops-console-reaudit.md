## FINDINGS
- F-C523-1 MEDIUM-LOW (PROVEN, real httpx): the guarded routes `POST /api/agents/{id}/kill|revive|drill`, `/api/tokens/{id}/revoke` and `/api/escalations/{id}/resolve` (read in the source: `f"/escalations/{escalation_id}/resolve"` to the governor; the bulk and halt routes build paths from body ids and I did not probe them) put the path parameter into the upstream URL unquoted (`f"/kill/{agent_id}"`), while the READ route `GET /api/agents/{id}` quotes it (`quote(agent_id, safe="")`). Starlette hands the handler the DECODED id, so an id sent as `a%3Fforce%3D1` becomes the upstream request `POST /kill/a?force=1` (a query string the caller chose); `a%23frag` becomes `POST /kill/a` (the fragment is dropped: the request kills agent `a`, not `a#frag`); `%2e%2e` becomes `POST /` (httpx collapses `/kill/..`); a space is encoded by httpx, CR and LF are refused by httpx (the console answers 502). All of these carry the forwarded operator pair. Impact: the caller is an authenticated operator acting within that operator's own scope, so this is not an escalation; it is a parameter and path injection toward the kill-switch and delegation services and an id-truncation hazard on the most sensitive action (`a#x` acts on `a`). Fix: `quote(agent_id, safe="")` (and the token and escalation ids) exactly as the read route does; tests: `%3F`, `%23` and `%2e%2e` ids must reach the upstream as `%3F`, `%23` and `%2E%2E` (the upstream then answers 404 for an unknown id), never as a query, a fragment or a path climb.
- F-C523-2 LOW (a mutant survives): `_operator_kw` forwards the pair only when both values are present (`if op and key`). The mutant `if op or key` (a half pair forwarded with a `None` value) survives all 117 tests of the console's six auth and feature test files. `parse_headers` returns `('don', None)` or `(None, 'k')` for a half pair, so the guard is the only thing that stops a half header reaching an upstream. Add a test: only `x-field-operator` sent (and only the key) under OFF and under ENFORCE: nothing forwarded under OFF, a 401 under ENFORCE.
- F-C523-3 LOW: an upstream's error body is relayed to the browser verbatim as `detail` (`_proxy`: `raise HTTPException(status or 502, detail=data)`). With a mock upstream answering 500 and a body naming a path and an environment line, the console's response carried it (`{"detail":{"detail":"Traceback ... FIELD_SHARED_SECRET=abc"}}`); an unreachable upstream gives `{"detail":"[Errno -2] Name or service not known"}` (class name and errno only, no URL). The page's setup screen withholds 5xx details client-side, but the API itself does not, so any caller holding the perimeter secret sees what an upstream said on a 5xx. Fix: for status >= 500 relay a fixed message and log the body server-side; keep 4xx verbatim (the refusals the operator needs).
- F-C523-4 OPEN CLASS (known, C-55 and C-56, PR 295 lint): `ServiceClient` builds `httpx.Client(base_url=..., timeout=10.0, headers=_console_headers())` with the default `trust_env=True`, so `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` in the console's environment would route the upstream calls, including the forwarded operator pair, through that proxy. The console's upstreams are on the compose network, so no proxy is expected; the fix is the shared constructor with `trust_env=False` from the C-56 plan.
