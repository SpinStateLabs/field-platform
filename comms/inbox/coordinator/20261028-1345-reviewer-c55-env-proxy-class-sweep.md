In the repo no compose file, Dockerfile or entrypoint sets a proxy variable (grep: none).

## The class
Both client libraries the repo uses build their transport from the process environment by default. If `http_proxy` / `HTTP_PROXY` / `ALL_PROXY` is set when the process starts (and `no_proxy` does not name the target), a plain-http request carrying `x-field-auth`, `x-field-operator-key` or an API key is sent to the proxy in clear. Docker itself can inject these variables into every container (`~/.docker/config.json` "proxies"), so "no compose file sets it" is not "no container has it".

## Proven (probe)
- httpx: `httpx.get("http://registry:8001/...", headers={x-field-auth, x-field-operator, x-field-operator-key})`, `httpx.Client(headers=...)` to `http://10.0.0.62:18080/...`: the proxy received BOTH the perimeter secret and the operator key in clear (request line `GET http://registry:8001/agents`). `trust_env=False` does not reach the proxy; `NO_PROXY=registry,10.0.0.62` does bypass it.
- urllib default opener: FieldClient (#48) sends x-field-auth to the proxy (C-41).

## Severity
MEDIUM overall: needs a proxy variable to be present in a process that also holds a secret, a condition I could not check; impact is disclosure of the estate-wide secret and operator keys in clear to whoever runs the proxy; the sandbox/agent containers (C-48) that hold the estate secret make the proxy question matter more. HIGH confidence in the code facts, LOW on exploitability in the live estate.

## Fix (one change covers the class)
1. A single factory in field_core (e.g. `field_core.http.client(**kw)` -> `httpx.Client(trust_env=False, follow_redirects=False, **kw)`), used by every internal caller; the https third-party callers (group 3) and the Fly witness keep proxy support only through an explicit, named `FIELD_EGRESS_PROXY` setting, never the ambient env. For urllib: `urllib.request.build_opener(urllib.request.ProxyHandler({}), _NoRedirect)`.
2. A CI lint (extends tools/topology_lint.py style, AST): in non-test code every `httpx.Client|get|post|request|stream` call must come from the factory or pass `trust_env=False`; every `urllib.request.urlopen` / `build_opener` must include `ProxyHandler({})`. 59 sites to convert, mechanical.
3. One parametrised test per client class with `http_proxy` set to a local listener asserting zero hits (my probe is the template; ~25 lines).
4. Runbook line: Docker `proxies` config and host `HTTP_PROXY` must not be set on the GB10, or `NO_PROXY` must list every service name and the GB10 address.
