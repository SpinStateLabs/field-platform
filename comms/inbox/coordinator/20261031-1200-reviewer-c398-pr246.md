## OBJECTIONS FIRST
1. F-C398-1 MEDIUM-LOW (unpinned bypass guard): the validator parses with `ipaddress.ip_network(entry.strip(), strict=False)`. The mutant `strict=True` SURVIVES all 47 tests of the new file and all 229 tests of the package. With `strict=True`, `1.2.3.4/0` (any address with a /0 or other wide prefix and host bits set) raises `ValueError`, the validator treats it as "not a network" and accepts it, and the matcher (`clauses.py:292`, `strict=False`) then reads it as `0.0.0.0/0` and AUTHORIZES every client: the D-20 catch-all through the side door. Today's code is correct (`1.2.3.4/0` and `203.0.113.5/7` both exit 1; `203.7.7.7/8` is accepted as the /8 it is), but no test has a wide network written with host bits.
2. F-C398-2 LOW: the IPv4-mapped boundary is unpinned. The mutant that reads `::ffff:a.b.c.d/95` as an IPv4 network (`prefix >= 95` instead of `>= 96`) survives all 229 tests. Today `::ffff:0.0.0.0/95` is accepted as an IPv6 /95; it matches no IPv4 client because the matcher normalises client addresses to IPv4 before comparing, so it widens nothing, but the edge is not pinned.
3. F-C398-3 LOW (by-design edges of a per-entry floor): the floor applies to each entry, not to the union. 256 entries of `/8` cover the whole IPv4 space and each is accepted; `64:ff9b::/96` (the NAT64 well-known prefix, every IPv4 client behind a NAT64 gateway) is an IPv6 /96, above the /32 floor, so it is accepted, as is `::/32`. The ruling and the card say /8 and /32, which is what is implemented; I list these because a reader may assume "a catch-all is impossible", which is true of one entry and not of the list. An operator who wants to silence the alert still cannot make the scan exit 0 (exit 3), which is the control that holds in every one of these cases.
4. F-C398-4 LOW: the stderr NOTE for exit 3 is unpinned (the mutant that prints it to stdout survives 229 tests); a malformed entry that is not a network at all (a leading-zero octet such as `010.0.0.0/8`, a typo) is silently accepted and matches nothing, as before, so a mistyped allowlist entry fails quiet in the direction of more alerts, not fewer. Fine; stated.
5. The tests changed in the PR: `test_detection_pins_c148.py` drops `0.0.0.0/0` and `::/0` from the list of entries a non-IP client is tested against (they are now refused at config build), and its scan test now expects 3, not 0, when every session is authorized. Both follow from the ruling; no other assertion is removed.
