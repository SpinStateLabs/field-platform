### C2 (MEDIUM, confirmed by running): a stored `-inf` ceiling reads as "no ceiling"
Probe (tk502b.py in my scratchpad; a token saved, then its row in `token_spend_ceilings` set with raw sqlite to each value): stored `+inf` gives `get`: None, `list`: [None]; stored `-inf` gives `get`: None, `list`: [None]; stored `-1.0` raises `ValidationError` on `get` and `list`; `0.0` and `5.0` read back exactly. `_finite_ceiling` tests `math.isfinite`, so `-inf` is mapped to None like `+inf`, and the PR's test pins it (`test_a_stored_infinite_ceiling_reads_as_no_ceiling...[minus-inf]`; my narrower mutant D9, `+inf` only, fails it). The PR's rationale covers +inf only ("an infinite cap never trips"). A negative-infinite ceiling means nothing may be spent; reading it as unlimited turns a corrupted or hand-edited row into the opposite of its meaning, while the finite negative `-1.0` is refused loudly. The API cannot write -inf (the model refuses it), so the exposure is a damaged database, not a request; but the sentinel enforces `E.spend_cap` from this value, so the failure is silent and in the unsafe direction.
Fix: map only `+inf` to None; let `-inf` raise like `-1.0` (change the pinned test's parameter list to `+inf` and add `-inf` as a refusal). NaN cannot be stored (`NOT NULL`: my probe's insert raised IntegrityError), so it needs no rule.
