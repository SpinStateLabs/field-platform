## Objections first (FORCE-O)
1. Sanitising at the Markdown sink protects the Markdown but not the JSON payload returned alongside it by `generate_pack` (the second value of the tuple): caller text such as `agent_id` or a gap detail still reaches that dict raw. That is right for structured data, but a consumer who renders the dict as Markdown or HTML inherits the same injection; the PR does not claim otherwise.
2. The sink list is a whitelist of the five call sites the reviewers found (title, evidence detail, pack agent_id, gap detail, stale-flag fields). A new caller-text field added later is unsafe by default; there is no test that scans for an f-string interpolation of an unsanitised variable. LOW.
3. The unpaired-surrogate refusal covers `agent_id` only; the signer's category set now includes `Cs` through the shared constant, but no test shows a signer containing a surrogate being refused (P10 survived), so the "cannot be encoded as UTF-8, a 500 on the response" failure for a signer is unpinned.
Steelman: one module owns the character policy, the signer and the Markdown share it (a change to the policy changes both), the escape is visible (`<U+XXXX>`), the length cap is counted after escaping and never cuts a token, the refusal is by name and does not echo the value, and 33 mutants were thrown at it.
