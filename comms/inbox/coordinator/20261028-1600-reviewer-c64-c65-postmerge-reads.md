### #44 (Fly per-process operator identities: entrypoint.sh +131, tools/fly_identity_check.py +232): PASS with conditions, READ ONLY, UNVERIFIED (no entrypoint run, no Fly)
14. MEDIUM (declared by the PR as "Fly (b) row"): the four daemon keys are 0600 files in a 0700 directory, but all thirteen processes of the one machine run as the SAME unix user, so every process can read every key file (and `/proc/<entrypoint pid>/environ` holds the secrets until exit; the PR says so). Per-process identity on Fly therefore gives ATTRIBUTION (which daemon acted), not isolation: one compromised service (the gateway and crosswalk face the internet through Caddy) reads svc-killswitch.key, which holds `bypass_operator_list`, and can act as the kill-switch under ENFORCE. If isolation is wanted: run each daemon under its own uid (the entrypoint is PID 1; `setpriv --reuid`/`su-exec` per launch block; chown each key to its daemon); otherwise keep the declaration in the runbook and do not count this as the "per-process identity" control for Stage 2.
15. LOW: an existing key file is truncated and rewritten ("keeps the 0600 it was created with", entrypoint.sh comment): if an earlier image or hand edit left it 0644 it stays 0644. Add `chmod 0600` after the write; fly_identity_check does verify 0600 in the running machine (not run).
16. Positive by reading: refuses to start when FIELD_OPERATOR / _KEY / _KEY_FILE are set machine-wide; all-four-or-none; each secret checked for a single key token and length <= 256, never printed; the key reaches no argv (printf builtin) and no service environment; none set = byte-identical behaviour.
