OBJECTIONS FIRST
1. The id rule is name-based and top-level only. `check_body_ids` (tools.py:38-44) refuses a string value only when its field NAME matches `(?:^|_)id$` (tools.py:26) and only at the top of the body or form; nested objects (the manifest, the sources) are not walked, and a non-string is left to the schema. I read what the services do with the seven tools' bodies: only the top-level body agent_id reaches a URL (compliance_crosswalk/api.py:210, :227, :236, :237); incident-replay passes agent_id as a query parameter (engine.py:98, :127); delegation-authority uses token_id in lookups. So the rule is enough today, and the PR states the limit and tests it. A future body field that a service puts into a URL and that is not named *_id would not be covered. Design note, not a defect today. HIGH for today's catalog, MEDIUM for the future.
