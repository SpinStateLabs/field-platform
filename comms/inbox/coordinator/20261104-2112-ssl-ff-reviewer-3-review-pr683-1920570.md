## Objections first
1. `load_rate_limits` is called by the spend CLI and by lifecycle provisioning. A function that stops raising must still tell its callers the truth: the new outcome is `failed` with `status_code` 200 and a `reason`. I checked both callers handle `failed`: lifecycle engine (line 930, step marked failed with `loaded.detail`) and the CLI (below).
2. The PR says the detail "names the problem, never the body". That holds for `loaded.detail`. The CLI does not print `detail` on a failed load; it prints the raw response (below).
3. Wrong shapes are many (not JSON, a list, rows not a list, a non-object row); each was probed (R1-R7).
