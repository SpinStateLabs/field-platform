# ROLE LOOP (coordinator 2026-11-04, Don: no duplicates, no idle builder, reviewer or verifier)

Every builder, reviewer and verifier session runs this loop forever. There is no step where you wait for a card, a PR or a target to be named.

1. Get the dispatcher: `git fetch origin comms; git show origin/comms:comms/tools/dispatch.sh > <scratch>/dispatch.sh` (always the latest copy). Run it with `bash <scratch>/dispatch.sh ...` from inside your field-platform checkout. It SETS the commit identity (Don Hagell noreply) over whatever the environment carries and refuses to push on a mismatch. Do not commit to `comms` any other way.
2. `bash dispatch.sh next <builder|reviewer|verifier> <your-session-name>`. Output `CLAIMED<TAB>id<TAB>role<TAB>target<TAB>note` means the item is yours: the claim is a lock on origin/comms, and git rejects a second claim of the same target, so nobody can duplicate you. Work it per your role below.
3. When the work is pushed: `bash dispatch.sh report <you> <slug> <report.md>`, then `bash dispatch.sh done <role> <target> "<one line>"`. Then go to step 2.
4. If a claimed item is wrong or already built, `bash dispatch.sh release <role> <target> "<why>"` and go to step 2. Never build a duplicate "to compare".
5. `EMPTY` (exit 3), or `bash dispatch.sh level` showing RESTOCK: write one report `restock-needed` naming the role. A scheduled restock (every 30 minutes, run by the coordinator's automation) refills WORKLIST.tsv; meanwhile run the role's FALLBACK below, then repeat step 2. Never stop and never ask Don.

Roles
- builder: verify the scout evidence on current main first. Bug: failing test first, minimal fix, one mutant. Test gap: tests only. One item = one branch = one draft PR against main. Run each service's tests in its venv with a RELATIVE PYTHONPATH (`PYTHONPATH='../../packages/field-core/src;src'`); install a missing module such as `typer` into your own venv or record the failure as a baseline measured on a clean main. Report the head SHA and what you ran. FALLBACK when EMPTY: scan one service under your lane area (Lane 1 tools, field-core, console; Lane 2 service tests; Lane 3 docs, runbooks, CI, compose) for a function no test names, write it up as a proposal in your report, and build it after `dispatch.sh` shows RESTOCK has not refilled within one pass.
- reviewer: independent (you did not write the head, and your lane did not build the PR). Read the diff on the EXACT head, at least 4 mutants per behaviour the PR claims to pin, a table with totals COUNTED FROM THE TABLE, verdict PASS / PASS WITH CONDITIONS / BLOCK naming the head SHA. After a PASS the head is frozen: only a condition fix may be pushed; optional LOWs go in a NEW PR. FALLBACK when EMPTY: take the oldest merged batch in STATUS.md without a reviewer note and review it read-only.
- verifier: for a `REPORT:` target, write the report from the finished run's log (per-suite counts, compare with the last green run, state that no count went down, head SHA); do not re-run. For a `RUN:` target: fetch the head from GitHub into `~/ff-work/wt-<name>`, `setsid nohup ~/ff-work/runbatch.sh <name>`, marker `~/ff-work/<name>-all.done`, log `<name>-all.log`; one full run per session; not while the load average is above 8. Docs-only PRs may use a LIGHT run and the report says "light run, docs only". Never feed stdin to the GX10 tool; never kill a process you did not start. FALLBACK when EMPTY: re-run the full set on current main and report any count that went down.

- docs: addition-only dated entries; verify every cite against the code on current main before writing it; no code changes; one item = one branch = one draft PR. FALLBACK when EMPTY: check one runbook or README against the code and fix the first contradiction found.
- groomer (keeps every queue full and duplicate-free; never merges, never closes a PR, never edits TASK-QUEUE.md or STATUS.md): run the restock scan: (1) open PRs with no verdict on the current head, (2) finished GX10 runs with no report, (3) proposals, BACKLOG items and OPEN cards proven unclaimed by grepping inbox, open PRs and branches; append them to WORKLIST.tsv (append only, unique target per role); (4) when unclaimed builder items fall below LOW_WATER (6), scout a service for untested functions and add them as builder items with evidence; (5) file duplicate-resolution notes. Run it every 30 minutes and whenever any role reports restock-needed.
- coordinator (the only merger): numbers cards, edits TASK-QUEUE.md, STATUS.md, WORKLIST.tsv; merges FAST-FORWARD ONLY after an independent reviewer PASS on the exact head and a green GX10 16/16 on that head rebased on current main; deploys, secret rotation and the live gate are escalations that wait for Don.

Rules for everyone: only the coordinator edits TASK-QUEUE.md, STATUS.md and WORKLIST.tsv, merges, deploys, rotates secrets or touches production. This repository is public: no estate address other than the sandbox fly.dev hostname, no flag value, build id, deploy status or credential. Models: Opus/Sonnet/Haiku, never Fable.
