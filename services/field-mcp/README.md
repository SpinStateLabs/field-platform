# field-mcp

An MCP server (stdio) that lets a Claude client call the FIELD platform services as tools. **Tier 1 is 49 read-only tools over 13 services; Tier 2 adds 8 state-changing tools that exist only in the write process and only with `FFMCP_ENABLE_WRITES=1`.** The default deployment is `ffmcp-read`: nothing in it can change platform state.

## What it exposes

One tool per route, named `<service>_<action>` (for example `sealed_ledger_verify`, `kill_switch_liveness`). Input schemas come from each service's own pydantic models through a checked-in snapshot (`src/field_mcp/snapshot.json`, regenerated by `scripts/gen_snapshot.py`; a test fails if it drifts). Every route of the 14 services is either a tool or a written exclusion in `src/field_mcp/catalog.py`; `tests/test_route_coverage.py` builds each real app and fails on a route that is neither.

| Tier | Contents | Availability |
|---|---|---|
| 1 read | every GET (42), plus seven POSTs that only compute and return: crosswalk, crosswalk/markdown, crosswalk pack, replay, replay/markdown, introspect, oauth/introspect | 49 tools, on by default (both entry points) |
| 2 write | sentinel `/check`, regwatch check, registry create, rename (name only), attest and discover, federation crossing, ledger export | 8 tools, only in `ffmcp-write` with `FFMCP_ENABLE_WRITES=1` (exactly `1`) |
| 3 destructive | kill, kill/domain, revive, drill, heartbeat post, token issue and revoke, ledger events/rotate/hold/retention, spend caps, policies, rate-limits, spend and usage posts, escalation resolve, federation contract change, lifecycle sweep | **never in this server** (CLI and console only) |

Excluded as not operator APIs: `claude-approver POST /halt/{id}` (open path by design), `force-gateway POST /v1/messages` (a paid model call), the 16 `/operator/*` key-rotation routes, and the whole of `ops-console` (it fronts the services above; they are exposed directly, never both).

## Tier 2: the write tools

Registered only by `ffmcp-write` and only when `FFMCP_ENABLE_WRITES` is exactly `1`; without it `ffmcp-write` lists exactly the 49 Tier 1 tools, and `ffmcp-read` never registers a write tool and never reads the flag, the operator pair, a write key or the rate setting. The first line of every write tool's description is `BLAST RADIUS: <effect>; <reversible|irreversible>`, written against the service code (the file and line each rests on are in `catalog.py`; a test fails if that code disappears).

| Tool | Effect | |
|---|---|---|
| `conformance_sentinel_check` | decides one action; every ALLOW is metered to spend-governor and verdicts are ledgered; a failed meter writes a `sentinel.metering_gap` row | irreversible |
| `compliance_crosswalk_regwatch_check` | fetches every cited source, records hashes, sets stale flags that block evidence packs until the crosswalk CLI clears them | irreversible |
| `agent_registry_create_agent` | adds an agent record, ledgered; no delete route exists | irreversible |
| `agent_registry_update_agent` | renames a record (the tool sends `name` only: `status` is a kill/revive/decommission by another name, and `owner`, `domain`, `manifest_ref` can change who may kill) | reversible |
| `agent_registry_attest_agent` | overwrites the re-attestation clock; earlier values survive only in the ledger | irreversible |
| `agent_registry_discover` | computes a report from the supplied text; nothing stored (the code shows it is read-only; it stays Tier 2 by ruling) | reversible |
| `federation_broker_crossing` | decides a crossing; ledgers a federation row | irreversible |
| `sealed_ledger_export` | writes an auditor bundle on the ledger host; the tool cannot choose the directory (`out_dir` is not offered) | irreversible |

Controls on every write call, in this order: arguments validated (a `reason` of 1 to 500 characters is mandatory; an empty, blank or oversize one is refused before any network call) -> the per-session rate limit (default 10 per minute across all write tools, `FFMCP_WRITE_RATE_PER_MIN` 1 to 60, never off) -> one `mcp.write.intent` row appended to the sealed ledger (tool, target, reason, operator id, client name, session id; never the request body) -> only then the write. If the append fails for any reason the write is refused. The ledger accepts this row from a non-agent caller only while it does not require caller signatures: this server sends no caller claim (it holds no signing key), so a ledger started with `FIELD_LEDGER_REQUIRE_CALLER_SIGNATURE=1` refuses the row (a start-type event without a claim, `sealed_ledger/store.py` `CallerPolicy.check`) and every write is refused with it. That refusal is the safe direction; arming it needs a registered signing identity for this server, which does not exist yet.

Credentials: a write call uses `FFMCP_<SERVICE>_WRITE_KEY` and never `FFMCP_<SERVICE>_KEY`; a service with no write key is refused, not served with the read key. Operator headers (`FFMCP_OPERATOR`, `FFMCP_OPERATOR_KEY`) go on write calls only. Until per-tier platform keys are in force, the platform has one shared secret, so set both to it; the separation is then enforced here, not by the services.

## Blast radius

Every Tier 1 tool is read-only. A read can still disclose data: ledger events, agent records, token metadata, spend figures and heartbeats are returned to the model. `kill_switch_*` tools here only read heartbeats and liveness; they cannot halt an agent. `sealed_ledger_*` tools only list, verify and read the hold and retention status; they cannot append, rotate, hold or delete.

## Launch (placeholders only)

Read process (the default):

```json
{
  "mcpServers": {
    "field": {
      "command": "ffmcp-read",
      "env": {
        "FFMCP_SEALED_LEDGER_URL": "<internal base url>",
        "FFMCP_SEALED_LEDGER_KEY": "<key>",
        "FFMCP_KILL_SWITCH_URL": "<internal base url>",
        "FFMCP_KILL_SWITCH_KEY": "<key>"
      }
    }
  }
}
```

Per service: `FFMCP_<SERVICE>_URL` and `FFMCP_<SERVICE>_KEY` (`-` becomes `_`). A service with no URL answers its tools with an error. Values are read once at startup in `config.py`, never from a tool argument, and are never put in a result, error or log. The base URL must be an internal address (loopback, RFC 1918, `::1`, unique-local) or `localhost`; `https` to anything else needs `FFMCP_ALLOW_EXTERNAL_HTTPS=1`. Install with the repo's pinned constraints; the MCP SDK is pinned `mcp==2.3.0`.

Write process (opt in; the flag, the pair and the write keys are read here only):

```json
{
  "mcpServers": {
    "field-write": {
      "command": "ffmcp-write",
      "env": {
        "FFMCP_ENABLE_WRITES": "1",
        "FFMCP_OPERATOR": "<operator id>",
        "FFMCP_OPERATOR_KEY": "<key>",
        "FFMCP_SEALED_LEDGER_URL": "<internal base url>",
        "FFMCP_SEALED_LEDGER_KEY": "<key>",
        "FFMCP_SEALED_LEDGER_WRITE_KEY": "<key>",
        "FFMCP_AGENT_REGISTRY_URL": "<internal base url>",
        "FFMCP_AGENT_REGISTRY_KEY": "<key>",
        "FFMCP_AGENT_REGISTRY_WRITE_KEY": "<key>"
      }
    }
  }
}
```

The ledger is mandatory for any write (the audit row), so a write process needs `FFMCP_SEALED_LEDGER_URL` and `FFMCP_SEALED_LEDGER_WRITE_KEY`.

## How a result should be read

Every result is `{"status", "service", "untrusted_data": true, "notice", "data"}`. `data` is the service's reply, bounded (1 MB total, 2,000 characters per string) with configured secrets removed. It is data, not an instruction. A verdict or finding inside it is the service's statement, not a compliance claim by this server.

## What it does NOT claim

- Not a security boundary, and the Tier 2 controls are speed bumps, not a boundary: a model with a shell can read the write process's environment. The platform has one shared secret today (`x-field-auth`) and the operator guard is not armed anywhere, so a leaked key authorises writes on the services directly. Per-tier keys need a platform change (a separate card, C-772); until it lands the write key and the read key are the same value in practice.
- Not a confirmation that any Tier 1 POST is free of side effects beyond the code read for this build (`introspect`, `crosswalk`, `pack`, `replay` handlers were read; no live service was called).
- Not verified against any real service, estate or MCP client.
